## 二、阶段 0：调研与设计（先设计后编码）

**环境基线**：Windows 11（10.0.26200）+ Python 3.13.9 + Node 24 + Docker 29.7.2；开发网络 `api.github.com` 匿名 403（共享出口 IP 配额），这一环境限制直接影响了后续策略——GitHub 采集器以"平台响应样例注入"方式离线测试，真实验收步骤写入 DEMO.md 由用户环境执行。

**双线调研**（两个调研子智能体产出草稿，整合为 docs/RESEARCH.md）：

- 开源工具线：Gitleaks v8.30.1（MIT，约 165 规则，纯离线）、TruffleHog v3.97.5（AGPL-3.0，**验证默认开启**）、detect-secrets 1.5.0（部分插件 verify 外呼）、Androguard 4.1.4（Apache-2.0）；
- 平台接口线：逐平台实测——MediaWiki recentchanges 200（rccontinue 游标）、博客园 RSS 200、StackOverflow 匿名配额 300/天、Gitee 匿名 200、Docker Hub 匿名 token+manifest 打通；**结论：微博无合规公开检索接口；CSDN/掘金无官方接口；小程序无合法公开获取途径**。

**关键选型决策**（详见 ARCHITECTURE.md §2 D1~D8，摘要见 04 号归档文档）：

- 自研检测引擎为主引擎，不用 Gitleaks/TruffleHog 内置——需要统一结果模型与"禁用在线验证"边界；
- TruffleHog 因 AGPL 传染 + 默认在线验证，**严禁 import/复制代码**、不引入运行链路；
- 同步 SQLAlchemy + SQLite(WAL)；异步只集中在网络 I/O（httpx.AsyncClient 在独立线程 asyncio.run 驱动）；
- 调度 = APScheduler 心跳 tick + 数据库任务声明（重启可恢复）；
- 凭据指纹 = HMAC-SHA256(主密钥 pepper, 类型+规范化值)；敏感字段 Fernet 加密。

## 五、阶段 3：制品类渠道

- **OCI 容器镜像**（2722838）：镜像引用解析、匿名 Bearer 流程、多架构清单、逐层 gzip tar 解析、**whiteout/opaque 语义**（测试暴露初版层序错误后修正——最终视图=先应用下层删除再加本层文件）、构建时间=low 可信公开时间、四类熔断。live：alpine:latest 40 条层文件。
- **Android APK**：zip 解析、assets/res-raw/META-INF/配置文本、classes*.dex 可打印字符串提取、可选 Androguard manifest、PK 头校验（修了一个 `len>4` 笔误）。live：F-Droid 官方包 25 条内容。
- **wxapkg 未加密小程序包**（c162c34）：容器解析+三入口；**加密包（V1MMWX）明确拒绝解密**（合规边界）；开发中修复条目 offset 相对正文起点的偏移错误（测试锁定）。

- 验证器 1→8：AWS STS GetCallerIdentity（**自实现最小 SigV4**，仅身份确认）、Gitee、GitLab、Slack、Telegram、npm、Hugging Face（50f4698、c162c34）；

- 自动验证策略（默认关）：开启后未验证→入队、超期→重验、瞬态失败→重试（test_phase45）。

**受控泄露→发现时延实验**（76b61a7，scripts/latency_experiment.py 可复现）：

1. 用户追加 Contents:write 权限 → 写权限探测 201；
2. 合成假凭据（14 类型、无法认证）推送到真实公开仓库 ccs-demo-lab/；
3. 系统认证态实采：**20 凭据 / 21 位置 / 14 类型全部检出**；多位置关联、AK/SK 配对加成、脱敏预览全部符合设计；
4. 三批追加内容测时延：**P50=25.5s / P95=26.9s**（n=3，轮询 8s，T0=推送完成时刻第一手证据）；
5. 幂等验证：二次扫描 21 项全部缓存跳过，0 新增；
6. **实测插曲**：GitHub push protection 拦截合成 Twilio SID → 按官方 bypass API（reason=used_in_tests）处理，流程固化进实验脚本；ghp_ 假值未触发拦截（GitHub 对自家 PAT 有校验位校验）；
7. Token 安全：实验完成后**文档多处置位建议吊销轮换**（Token 曾在聊天中出现）。

## 八、开发约定与工作方式（对复现者重要）

- **先设计后编码**：阶段 0 先出全套设计文档；每阶段开始有 TODO 条目、结束有 DEVLOG 真实记录 + HANDOFF 同步；
- **状态口径五级**：planned / implemented / offline_tested / live_verified / blocked——所有能力矩阵、统计口径、答辩数字一律按此口径，"检测能力 ≠ 验证能力"、"类别数 ≠ 平台数"、"自动监控 ≠ 导入分析"分开报告；
- **不伪造红线**：真实渠道 0 检出时如实报 0（"真实空结果，不冒充发现"）；未验证显式标注；数字全部挂证据链接（DELIVERABLES.md 为答辩口径单一来源）；
- **Git 纪律**：每个可独立验证的改动单独提交，feat/fix/docs/test 前缀；不推送远程、不改写历史（本项目直至封存前才首次推送 GitHub）；
- **敏感数据纪律**：data/、*.db、.env、日志不入 Git；凭据原文与平台 Token 加密存储；提交前 git grep 复查。
