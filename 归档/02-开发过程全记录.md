### 6.4 自动验证策略（test_phase45 锁定）

## 九、贯穿全程的开发约定（复现者视角）

1. **先设计后编码**：阶段 0 先出全套设计文档；每任务在 TODO 有条目、在 DEVLOG 有真实记录、会话末 HANDOFF 同步；
2. **状态口径五级**：planned / implemented / offline_tested / live_verified / blocked——所有能力矩阵、统计、答辩数字一律按此；"检测 ≠ 验证"、"类别数 ≠ 平台数"、"自动监控 ≠ 导入分析"分开报告；
3. **不伪造红线**：真实渠道 0 检出如实报 0；未验证显式标注；数字全部挂证据链接；
4. **Git 纪律**：每完成一个可独立验证的改动单独提交；不推送远程、不改写历史（归档日经用户要求首次推送，之后依旧不改写历史）；
5. **敏感数据纪律**：data/、*.db、.env、日志不入 Git；凭据原文与平台 Token Fernet 加密；提交前 git grep 复查；
6. **测试先行于"完成"声明**：done 状态必须附验收命令与真实结果（写在 DEVLOG）；每个修复至少一个回归测试。
