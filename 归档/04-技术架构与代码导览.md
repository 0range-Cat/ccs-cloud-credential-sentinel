# 04 · 技术架构与代码导览

> 归档时间：2026-10-08。本文给接手开发者用：架构、目录、模块边界、关键技术决策、数据模型。权威设计文档在 `docs/ARCHITECTURE.md` 与 `docs/INTERFACES.md`，本文是其导览与补充。

## 一、总体形态

**模块化单体**，单机可持续运行，可选 Docker Compose。不做微服务，不引入 Redis/K8s。

## 三、模块边界（铁律，改动前先读）

- `collectors/*` 只产出 `ContentItem`（平台元数据+内容+版本+时间信息），**不接触数据库写入**、不做检测；
- `detection/*` 只消费文本产出候选，**不知道来源是什么平台**；
- `pipeline.py` 是**唯一**同时理解采集与检测结果的组装层；
- `verification/*` **不 import** collectors/detection 的任何运行时逻辑，只通过凭据实体接口；
- `api/*` 只调 services 层，不直接拼 ORM 查询（导出除外，走专用流式查询）；
- 采集层允许 follow_redirects=True（镜像 blob 307 到 CDN）；**验证器严格 follow_redirects=False 且校验最终域名**——两个模块语义刻意不同，勿"统一"。

## 四、关键技术决策（ADR 摘要，权威=ARCHITECTURE.md §2）

| # | 决策 | 理由 | 改动影响 |
| --- | --- | --- | --- |
| D1 | 自研检测引擎为主引擎（YAML 规则注册表），不以 Gitleaks/TruffleHog 为内置主引擎 | 需统一结果模型（配对/上下文/置信度/多位置）与"禁用在线验证"边界 | 引入 gitleaks 走 detection/adapters，不改数据模型 |
| D2 | 数据库同步 SQLAlchemy；采集用 httpx.AsyncClient 在独立 worker 线程内 asyncio.run 驱动 | SQLite+同步 ORM 最稳；异步只集中在网络 I/O | 换 PostgreSQL 仅改连接串（已实测） |
| D3 | 调度 = APScheduler 心跳 tick + 数据库任务声明（UPDATE claim） | 任务/游标/结果全持久化，重启可恢复 | 无 |
| D4 | 凭据指纹 = HMAC-SHA256(主密钥派生 pepper, 类型+"\0"+规范化值) | 稳定、不可对外反推 | pepper 变化会导致历史指纹失效 |
| D5 | 敏感字段（凭据原文、配对字段、平台 Token）Fernet 加密 | 主密钥来自 CCS_MASTER_KEY 环境变量或 data/master.key（自动生成，0600） | **备份必须含主密钥** |
| D6 | Web 单用户：默认绑定 127.0.0.1；可选 CCS_ACCESS_TOKEN 开启简单口令 | 不建多人权限体系，远程部署需基础保护 | 无 |
| D7 | 验证模块完全独立：验证器仅声明固定服务端点；默认 auto_verify=false | 采集到的一切地址不得自动成为验证目标 | 无 |
| D8 | 资源限制内建：内容大小上限、正则输入截断、解包总量/比率限制、路径穿越拒绝、并发/速率可配置 | 防解压炸弹、防回溯输入放大、控内存 | 无 |
| D9 | 采集游标统一走 collector.cursors dict + 流水线持久化 | 采集器不接触 DB | 无 |
| D10 | 统一合规 User-Agent 常量 base.USER_AGENT | 维基媒体拒绝通用 UA（403） | 无 |
| D11 | 历史提交时间作"公开时间"仅记 low 可信，不参与分钟级时延统计 | 时间口径诚实性 | 无 |

## 五、数据模型（13 张表，权威=INTERFACES.md §1）

| 实体 | 关键字段 | 语义 |
| --- | --- | --- |
| Source 采集源 | name, category, platform, collector_key, config_json(seeds/include/exclude/budget/schedule) | 渠道接入定义 |
| Task 监控任务 | source_id, mode(manual/continuous), status, interval_sec, next_run_at | 每来源一个执行实例 |
| ScanRun 执行批次 | task_id, status, trigger, stats_json | 每次执行一条 |
| Cursor 采集游标 | task_id, cursor_key, cursor_value | 唯一(task_id,cursor_key) |
| SourceContent 来源内容 | source_id, version_id, path, content_hash, content, published_at(+source+confidence), fetched_at | 版本缓存唯一(source_id,version_id,path,content_hash) |
| Credential 凭据实体 | fingerprint(唯一HMAC), type, rule_id, confidence, secret_encrypted, paired_encrypted, review_status, verification_status, first/last_seen_at | 去重后的"同一凭据" |
| Occurrence 出现位置 | credential_id, content_id, location_hash(唯一), line_start, context_masked, evidence_json | "同一次出现" |
| ReviewLog 复核/审计 | credential_id, action(confirm/false_positive/ignore/restore/reveal_access), note, actor | 人工操作全留痕 |
| VerificationJob / Result | job 状态队列；result 每次验证追加不覆盖 | 验证历史 |
| RuleRecord 规则 | id(稳定主键), type, vendor, version, enabled | 启动时从 YAML 同步 |
| IgnoreRule 忽略规则 | scope_type/scope_value/reason | 命中=标记 ignored 不删除 |
| AppSetting | key, value_json, sensitive | sensitive=true 加密 |
| Capability 能力清单 | kind(collector/verifier/channel/rule), status(planned/…/live_verified) | "渠道与规则"页数据源 |

**时间字段语义**（全 UTC 存储，界面默认 Asia/Shanghai）：`source_published_at` 必须带证据来源与可信度（none/low/medium/high），无证据=NULL 显示"未知"；Git 提交时间/文件 mtime/首次抓取时间**不得冒充**公开时间。

**验证状态机（11 态）**：not_requested / queued / running / valid / invalid / inconclusive / missing_context / unsupported / rate_limited / network_error / error。规则：401/403 不一律 invalid；限流/网络故障不算 invalid；每次验证追加历史。

## 六、插件契约（新增能力只改插件层）

### 6.1 新增采集器（一个 Python 类）

```python
class MyCollector(BaseCollector):
    key = "my_channel"; category = "code_hosting"; platform = "my_platform"; version = "1"
    def __init__(self, config: dict, settings_svc): ...
    async def items(self) -> AsyncIterator[ContentItem]: ...   # 增量依据 config/cursors
    def test_connection(self) -> dict: ...
```

预算（max_items/max_bytes/max_seconds）、限流（429/403+Retry-After → rate_limited 优雅停止）、游标持久化、去重、入库、界面展示全部由框架承担。**实证**：开发当天新增 6 个采集器全走同一套测试与 live 验收。

### 6.2 新增凭据规则（一个 YAML 条目）

规则文件在 `backend/app/detection/rules/`，字段含：稳定 id、title、type、vendor、version、license、patterns、secret_group、min/max_length、min_entropy、required_context、forbidden_context、known_examples、pairing{with,max_line_distance,boost}、confidence、verifier、**tests{positives,negatives}**（注册表自检+pytest 共用——正例必须命中、反例必须不误报）。

### 6.3 新增验证器（一个类 + 合规硬性要求）

```python
class MyVerifier(BaseVerifier):
    id = "my-verifier"; supported_types = [...]; required_fields = [...]
    endpoint_hint = "固定官方端点说明"   # 禁止把采集内容当目标
    async def verify(self, cred, settings_svc, http_factory) -> Outcome: ...
```

硬性要求：最小请求；`follow_redirects=False` 且校验最终域名；不枚举资源、不读业务数据、无写操作；无满足要求的验证方式 → **不实现**，Capability 标 unsupported（保留检测）。

## 七、并发与资源模型

- 线程池 `CCS_WORKERS`（默认 2）；任务预算在 source.config_json；
- per-host 最小间隔 + 429/403 读 Retry-After，超限记 rate_limited 结束本轮；
- 稳定轮询加 ±10% 抖动；同一任务 DB 声明保证不并行；
- 解包目录 data/tmp/ 有总量配额与过期清理；data/cache/ 存原始内容副本（可配保留天数）。

## 八、安全基线

- 本地默认 127.0.0.1；远程走反代或开 CCS_ACCESS_TOKEN（POST /api/login，cookie 会话）；
- 凭据原文/平台 Token Fernet 加密；reveal 接口留审计（review_logs action=reveal_access）；
- 日志不打印凭据原文、完整上下文、平台 Token；
- CSV 导出防公式注入（=+-@ 前缀转义）；大导出流式响应。
