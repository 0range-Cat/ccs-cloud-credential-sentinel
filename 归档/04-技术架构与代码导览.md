**一次持续监控轮询的完整数据流**：APScheduler tick（20s）→ 发现到期任务 → 线程池领取（两级防重叠）→ 创建 ScanRun 批次 → collector 按游标/条件请求拉取 ContentItem → 版本缓存查重（命中跳过）→ 检测引擎产候选 → 忽略规则过滤（标记不删除）→ 指纹/位置双层去重入库 → 批次统计落库 → 游标持久化 → next_run_at 加 ±10% 抖动。

## 三、模块边界（铁律，改动前先背一遍）

1. `collectors/*` 只产出 ContentItem，**不接触数据库写入**、不做检测；
2. `detection/*` 只消费文本产出候选，**不知道来源平台**；
3. `pipeline.py` 是**唯一**同时理解采集与检测结果的组装层；
4. `verification/*` **不 import** collectors/detection 运行时逻辑，只通过凭据实体接口；
5. `api/*` 只调 services 层，不直接拼 ORM（导出除外，专用流式查询）；
6. **采集层允许 follow_redirects=True（镜像 blob 307→CDN）；验证器严格 False 且校验最终域名**——两个模块语义刻意不同，勿"顺手统一"；
7. 验证器禁止把采集内容地址当验证目标；连接测试只用设置页采集账号。

## 四、关键技术决策（ADR，权威=ARCHITECTURE.md §2）

| # | 决策 | 理由 | 改动影响 |
| --- | --- | --- | --- |
| D1 | 自研检测引擎为主引擎（YAML 注册表），不以 Gitleaks/TruffleHog 为内置主引擎 | 统一结果模型（配对/上下文/置信度/多位置）+ "检测禁验证"边界 | 引 gitleaks 走 detection/adapters，不动数据模型 |
| D2 | 同步 SQLAlchemy；httpx.AsyncClient 在独立 worker 线程 asyncio.run 驱动 | SQLite+同步 ORM 最稳；异步只集中网络 I/O | 换 PostgreSQL 仅改连接串（PG16 已实测） |
| D3 | 调度 = APScheduler 心跳 tick + 数据库任务声明（UPDATE claim） | 全持久化可恢复；APScheduler 不承载任务状态 | 无 |
| D4 | 指纹 = HMAC-SHA256(pepper=sha256("ccs-fingerprint-v1:"+主密钥), 类型+"\0"+值[+"\0"k=v…]) | 稳定可重算、不可反推、低熵密码不暴露普通哈希 | pepper 变化→历史指纹失效 |
| D5 | 敏感字段 Fernet 加密；主密钥 CCS_MASTER_KEY 环境变量 > data/master.key（自动生成） | 密钥外部化 | **备份必须含主密钥** |
| D6 | Web 单用户：默认 127.0.0.1；CCS_ACCESS_TOKEN 可选口令 | 不建多人权限；远程需基础保护 | 无 |
| D7 | 验证模块完全独立；auto_verify 默认 false | 采集地址不得自动成为验证目标 | 无 |
| D8 | 资源限制内建：1MB 检测输入截断/解包总量比率限制/穿越拒绝/并发速率可配 | 防炸弹/防回溯放大/控内存 | 无 |
| D9 | 游标统一 collector.cursors dict + 流水线持久化 | 采集器不碰 DB | 无 |
| D10 | 统一合规 UA 常量 base.USER_AGENT | 维基媒体拒通用 UA（403 实测） | 无 |
| D11 | 历史提交时间作公开时间仅记 low 可信，不参与分钟级时延统计 | 时间口径诚实性 | 无 |

## 五、逐模块函数级导览

### 5.1 应用入口 main.py

- `init_db()`：Alembic 迁移，异常回退 `create_all`；
- `lifespan(app)`：init_db → `services.sync_rule_records`（enabled 跨重启保留）+ `seed_capabilities`（只增不覆盖已演进状态）→ `scheduler.start_background()` + `verification.worker.start_worker()`（`CCS_BACKGROUND=false` 全禁，测试用）；
- `create_app()`：可选令牌中间件（cookie httponly / Bearer 双通道，`/api/login` 换发）→ `/api` 路由 → 静态托管（`CCS_STATIC_DIR` 或 frontend/dist）。

### 5.2 检测子系统 detection/

**registry.py**：`Rule` dataclass（20 字段：id/title/type/vendor/version/patterns 预编译/secret_group/min_max_length/min_entropy/required_context/forbidden_context/known_examples/pairing/confidence/verifier/structured/capture_block/tests…）；`load()` 校验必填并聚合 file_sha；`validate_tests()` 对每条规则跑自带正反样例——**样例即测试即文档**。

**engine.py** `DetectionEngine.scan(content, path, depth)` 七步管线：

1. 输入 >1MB 截断（`input_truncated` 标记入证据）；
2. 逐规则扫描，三种模式分流：`_scan_regex`（常规正则+secret 命名组）、`_scan_block`（PEM 私钥块捕获，含加密状态判定 OpenSSH=unknown）、`_scan_structured`（GCP 服务账号 JSON 结构化解析，提取 private_key+client_email+project_id）；
3. 逐候选拒绝链：长度窗 → 占位符/已知示例（`rejected=placeholder_or_example`）→ forbidden_secret_values（作用于捕获值及全部捕获组）→ 熵 → forbidden_context（命中行±context_window 行窗口）；
4. `_scan_base64`：有边界 Base64 解码（深度≤2、最多 20 次、解出文本递归扫描，`decoded_base64` 标记）；
5. `_resolve_overlaps`：跨规则重叠消解（同 span 保留高置信）；
6. `_apply_pairing`：AK/SK 配对（同文件行距≤max_line_distance）→ 双方置信度 +boost，且**配对字段值进入指纹输入**（AWS 指纹区分不同账号）；
7. 输出 `Candidate`（rule_id/version/type/vendor/secret/confidence/行号/span/verifier_id/evidence）+ rejected 候选（带 rejected 原因，供界面与忽略规则使用）。

### 5.4 流水线 pipeline.py

- `run_task(task_id, trigger)`：两级防重叠（tick 置 running + run_task 再校验 already_running）→ 创建 ScanRun → `_merge_config`（来源预算覆盖全局默认）→ `_build_collector`（注入 cursor_store 与平台 Token）→ `_execute` → 批次统计/状态落库 → `_persist_cursors` → 持续任务写 next_run_at（interval×U(0.9,1.1)）。异常分级：CollectorError/未知 → failed+last_error；**限流 → 正常停止+rate_limited 标记（不是失败）**；
- `_execute`：`_run_async` 驱动采集器（事件循环探测：worker 线程直接 asyncio.run；API 上下文另起单线程池——嵌套 asyncio.run 报错的修复）；逐项：版本缓存查重（唯一四元组命中即 skipped）→ 内容落库（截断 200KB）→ 检测（排除 rejected）→ `match_ignore_rules`（rule/path_glob/fingerprint_prefix/category 四作用域）→ `ingest_candidate` 入库；每项提交事务。

### 5.5 调度 scheduler.py

`start_background`（recover_interrupted + APScheduler 心跳）→ `_tick`（到期 continuous 任务领取 + `auto_enqueue_due` 自动验证策略调用）→ `trigger_manual_run`（触发不置状态，统一由 run_task 领取——防语义冲突的历史修复；执行器未启动时同步回退，测试友好）→ `recover_interrupted`（上次 running 批次标 interrupted，任务回 pending；结合版本缓存重启天然幂等）。

### 5.6 验证子系统 verification/

- `base.py`：`CredentialView`（解密最小视图）、`Outcome(status, evidence, latency_ms)`、`BaseVerifier.missing_context` 预检、`verifier_for_type`、`register`（传类自动实例化）；
- `verifiers.py` 8 个验证器 + `_sigv4_headers`（stdlib 最小 AWS4-HMAC-SHA256：GET+空载荷，host/x-amz-date 签名头）。状态映射纪律：200→valid；401→invalid；**403 分语义**（GitHub 配额头=rate_limited、GitLab 权限不足=inconclusive、AWS SigV4 拒签=invalid）；429/backoff→rate_limited；5xx→inconclusive；网络异常→network_error；响应体永不入库（Slack/Telegram 只取 ok/error 标志）；
- `worker.py`：`enqueue`（无验证器类型立即落 unsupported 结果）→ `_process_job`（解密→missing_context 预检→asyncio.run(verify)→结果追加→凭据状态更新）→ `_loop`（队列线程，per-verifier 限速 `verification.max_per_minute` 默认 10）→ `http_factory`（**返回即客户端**——"工厂的工厂"契约错误的历史修复）；`auto_enqueue_due` 自动策略（§03-9.1）。

### 5.7 业务服务与 API services.py / api/

- `ingest_candidate`：指纹 get_or_create（存在仅更新 last_seen+置信度取最大）→ location_hash get_or_create（同凭据多位置关联）→ ReviewLog 审计；
- `review_credential`：confirm/false_positive/ignore/restore 四转换全留痕；`reveal_credential`：解密+写 reveal_access 审计；
- `overview_stats`：分口径统计（命中/去重/位置/复核/验证分布/最近批次/时延 P50·P95——只取 published_confidence∈(medium,high) 样本并显示样本数）；
- `export_csv`/`csv_escape_cell`：公式注入防护（首字符∈{=,+,−,@} 前加 `'`）+ 流式生成；
- api/ 9 组路由 36 端点（全表见归档/03 §六）；settings_api 连接测试用**采集账号**（与发现凭据隔离）。

### 5.8 安全设施 security.py

`_master_secret()`（两级来源+自动生成 0600）→ `_fernet()` → `encrypt_text/decrypt_text`；`credential_fingerprint`（HMAC+pepper）；`location_hash`；`mask_preview`（头部 2~6 字符+`****`+尾部 2~4）；`shannon_entropy`；`is_placeholder`。

### 5.9 数据库 db.py / models.py

SQLite 连接事件挂 PRAGMA（WAL、外键、busy_timeout、NORMAL）；`utcnow()` 全库 naive UTC。13 表与字段全表见 docs/INTERFACES.md §1（归档/03 有摘要）；唯一约束三闸门：source_contents(source_id,version_id,path,content_hash)、credentials.fingerprint、occurrences(credential_id,location_hash)。

### 5.10 前端 frontend/

Vue3 `<script setup>` + Element Plus + hash 路由（免服务端路由配置、base:'./' 相对路径适配容器托管）；六页职责见归档/03 §2.2；`api.ts` 统一 axios + 状态中文映射；`npm run build` 产物由后端 StaticFiles 托管。

## 七、新增能力操作手册（三个扩展点）

### 7.1 新增采集器（八步清单，实证可行）

1. 调研平台公开接口/认证/限流/增量游标/公开时间可得性（写 docs/RESEARCH.md）；
2. 实现 `collectors/<key>.py`（契约+三条纪律：不写库、不做检测、遵守预算与限流）；
3. `base.py` 注册 import（1 行）；
4. mock 测试（httpx.MockTransport 注入：happy path / 限流 403+配额头 / 401 / 异常格式 / 边界）；
5. `CHANNEL_CAPABILITIES`（services.py）加能力行，状态先 offline_tested；
6. 真实渠道两轮 live 验证（scripts/live_check.py 式），通过后升 live_verified；
7. 更新 SUPPORT_MATRIX / SUPPORTED_CHANNELS / DELIVERABLES 数字；
8. 提交（采集器+测试+文档各自小提交）。

**数据库、前端、导出、复核、验证入口、统计全程零改动**。实证：单日新增 6 采集器各 140~330 行全走通（EXTENSIBILITY §四）。

### 7.2 新增凭据规则（零 Python 代码）

往 `backend/app/detection/rules/` 任一 YAML 追加条目：稳定 id（不改名）/title/type/vendor/version/license/patterns/secret_group/min_max_length/min_entropy/required_context/forbidden_context/known_examples/pairing/confidence/verifier/**tests{positives,negatives}**——注册表自检+pytest 共用，正例必命中、反例必不误报。

### 7.3 新增验证器（一个类 + 合规硬性要求）

继承 BaseVerifier：id/version/supported_types/required_fields/endpoint_hint（固定官方端点）+ `missing_context()` + `verify()` 返回 Outcome。硬性要求：最小请求；follow_redirects=False 且校验最终域名；不枚举/不读业务/无写操作；无合规方式则**不实现**，Capability 标 unsupported（保留检测）。

## 八、测试体系与可注入性
