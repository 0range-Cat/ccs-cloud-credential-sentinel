# 07 · 遗留问题与接手指南

> 归档时间：2026-10-08。本文是接手者的行动地图：接手前必知事项、第一周建议做什么、长期维护注意什么、哪些红线不能碰。

## 一、接手前必知（五件事）

1. **项目不是"半成品"**：阶段 5 全部可闭环项已完成，剩余项都是"待外部条件"或"已如实标注的合规受限"——不要把 blocked/planned/unsupported 误读为"没做完的 bug"。
2. **状态口径是项目的生命线**：planned / implemented / offline_tested / live_verified / blocked 五级口径贯穿全部文档与界面。你做的任何改动都要维护这套口径；答辩/汇报口径以 `docs/DELIVERABLES.md` 为单一来源。
3. **合规边界是硬约束**：验证只做最小认证；检测阶段禁用第三方在线验证；无合规接口的渠道不做绕过；加密小程序包不解密。**接手后任何"能不能顺手绕过"的念头都应被这个边界否决。**
4. **敏感数据纪律**：`data/`（数据库/主密钥/Token/实验数据）永远不入 Git；凭据原文与平台 Token 必须加密存储；界面脱敏 ≠ 可以把凭据写进日志/URL/异常。
5. **AGENTS.md 是本项目开发规则**：先设计后编码、状态口径、不伪造、Git 纪律、技术栈锁定——接手者必须先读它（项目根目录）。

## 二、安全第一课：Token 吊销确认

项目实验阶段曾使用用户提供 GitHub fine-grained PAT（含 Contents:write，曾在聊天中出现）。文档多处建议实验后**吊销轮换**，最后一次记录（2026-09-20）显示该 Token 已失效（401 Bad credentials，推测已吊销）。

接手者第一步：

1. 向原作者确认 Token 已吊销（GitHub → Settings → Developer settings → Personal access tokens）；
2. 若未吊销，立即在 GitHub 上 Revoke；
3. 删除本地残留：`data/github.token`（gitignored，但文件可能仍在）+ 设置库中的加密 Token（设置页清除）。

## 五、开发操作规范（沿用项目既有约定）

1. **先设计后编码**：实现前更新 docs/TODO.md 与相关设计文档；完成后同步受影响文档；
2. **Git**：每完成一个可独立验证的改动即提交（feat/fix/docs/test/refactor/chore 前缀）；不推送远程、不改写历史（注：2026-10-08 归档时已按用户要求首次推送 GitHub，此后按需推送即可）；不覆盖无关文件；
3. **提交检查单**：pytest 通过 / 前端可构建（若改动前端）/ 文档同步 / 未提交敏感数据；
4. **测试基线**：任何改动前先跑 `cd backend && python -m pytest` 确认 74 passed 起步；改动后不得低于该基线；
5. **空接口/静态页面/模拟数据不算实现**；没有测试证据不得标 done；done 必须附验收命令与真实结果（写 DEVLOG.md）。

## 六、红线（无条件，接手者必须逐条确认理解）

1. 密钥/令牌/密码绝不写入代码、文档、提交或对话；泄露立即撤销轮换；
2. 重大改动/不可逆操作前必建回滚点（git 干净基线 commit）；
3. 不伪造：不伪造调研结果、测试结果；不把模拟 valid 计入真实发现；
4. 验证模块只做"判断认证状态的最小操作"：不读业务数据、不枚举资源、不试用计费功能；默认关闭；禁止把采集到的凭据发送到与其所属服务无关的第三方；
5. 检测阶段禁用第三方引擎自带的在线验证；不引入绕过平台访问控制的能力；
6. `data/`、`*.db`、`.env`、日志、解包产物一律不入 Git；
7. 技术栈锁定（Python 3.11+/FastAPI/SQLAlchemy 2/Alembic/SQLite(WAL)→PostgreSQL/httpx/APScheduler/Vue3+TS+Vite+Element Plus）：变更选型必须先在 ARCHITECTURE.md 写理由。

## 七、如果只保留一条记忆

> **这个项目最值钱的不只是代码，而是"每个能力边界都有书面结论与证据"的工程纪律**——blocked 是结论不是缺陷，unsupported 是合规选择不是偷懒，0 检出是真实结果不是失败。接手后无论改什么，保住这套口径的可信度，项目的价值就不会贬值。
