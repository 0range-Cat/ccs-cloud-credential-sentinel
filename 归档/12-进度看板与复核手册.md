## 三、进行中项恢复脚本（逐命令）

### 3.1 种子组织→仓库扩展 live（对应卡 A-2）

```
1. 确认新 Token：curl -H "Authorization: Bearer <新只读TOKEN>" https://api.github.com/user   → 200
2. 设置页【平台采集账号】填入该 Token（或 PUT /api/settings）→ 测试连接
3. curl -X POST http://127.0.0.1:8000/api/discover/seed -H "Content-Type: application/json" \
     -d '{"platform":"github","orgs":["github"],"limit":5}'        # body 字段以 discover.py SeedIn 为准
4. GET /api/sources 确认生成 5 个 GitHub 来源 → 任选一个 POST /api/sources/{id}/run
5. 核对：批次 items_seen>0；组织仓库列表与 github/orgs 实际公开仓库一致（受 limit 限制）
6. 收口：DEVLOG 记录 + docs/TODO T2.6 补 live 标注 + SUPPORT_MATRIX/DELIVERABLES 如涉数字
```

### 3.2 验证器 valid 回填（对应卡 A-1；以 GitHub 已有双例为模板）

```
对每个有自有凭据的平台（Gitee/GitLab/Slack/Telegram/npm/HF/AWS 配对）：
1. 参考 backend/app/verification/base.py 的 CredentialView 与 verify() 签名，写 10 行直调脚本（占位示例，以实际契约为准）：
   from app.verification.base import CredentialView
   from app.verification.verifiers import GiteeTokenVerifier
   import asyncio, httpx
   outcome = asyncio.run(GiteeTokenVerifier().verify(
       CredentialView(type="gitee_token", secret="<你的自有令牌>", paired={}),
       settings_svc=None, http_factory=httpx.AsyncClient))
   print(outcome.status, outcome.evidence, outcome.latency_ms)
2. 预期：status="valid"，evidence 只含 endpoint+http_status
3. 记录：EVALUATION §4 新小节逐平台一行（平台/端点/状态码/时延）→ DELIVERABLES 评价 2 数字升级
4. 红线：脚本不落盘、凭据不进任何文件/Git；用完即弃
```
