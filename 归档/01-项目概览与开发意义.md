## 一、项目背景：赛题与真实威胁

### 1.1 赛题原文要求（来自 docs/MASTER_PROMPT.md 存档）

网络安全创新大赛赛题——"云上凭据泄露的自动化检测"，要求参赛系统：

1. **多公开渠道**检索泄露凭据（代码托管、Wiki、微博、知识分享、容器镜像、App、小程序共 7 类）；
2. 支持**尽可能多的凭据类型**（类型覆盖由参赛队调研后提出并落实）；
3. **分钟级发现**（从凭据公开到系统发现的时间差）；
4. **易于新增渠道**（可扩展性是独立评价指标）；
5. 交付四件套：**源代码、技术说明书、支持的公开渠道列表、支持的凭据类型列表**。

### 1.2 解决的真实安全问题

开发者经常把 API Key、云厂商 AK/SK、数据库口令、私钥、服务账号凭据写进代码、配置文件、博客文章、Docker 镜像层、APK 资源文件，并无意间推送到公开渠道。攻击者通过公开渠道搜索这些凭据即可直接利用，导致：云账户异常扣费（挖矿/流量盗用）、对象存储数据泄露、数据库被删或被勒索、域名/邮件服务被劫持。

真实案例背景（调研记录于 docs/RESEARCH.md）：Gitleaks 一类工具维护着上百条规则，说明"凭据意外公开"是持续高频发生的行业问题；TruffleHog 内置 700+ 检测器且默认开启在线验证，说明"验证凭据是否仍有效"是攻击链的关键一步——而现有开源工具普遍缺少的是**防守方视角的持续监控 + 诚实的口径管理 + 合规的验证边界**。

### 1.3 本项目的应对思路（与现有工具的差异定位）

| 现有工具 | 本项目（CCS）的差异 |
| --- | --- |
| Gitleaks/detect-secrets：一次性 CLI 扫描，只给正则结果 | **持续监控平台**：来源任务+调度+游标增量+批次统计，重复扫描零成本 |
| TruffleHog：验证默认开启，验证行为不受控 | **验证默认关闭**，8 个验证器全部"固定端点最小认证"，检测与验证物理隔离（不同模块、不同线程、检测链路零验证请求并有测试断言） |
| 多数工具把"抓到的时间"当"泄露时间" | **七类时间字段分离**，无证据的公开时间显示"未知"，绝不参与时延统计——时延数字经得起追问 |
| 工具结果零散、无台账 | 凭据实体与出现位置分离建模，同凭据多位置关联、重复发现去重、复核/验证/审计全留痕 |

## 二、系统是什么：功能全景

### 2.1 一句话定义

**云上凭据泄露自动化检测与响应系统（CCS，Cloud Credential Sentinel）**：单机可持续运行的中文 Web 平台，对公开渠道做"采集 → 检测 → 入库去重 → 人工复核 → 可选最小化验证 → 脱敏展示与导出"的完整闭环。

### 2.2 六个业务环节逐个说明

**① 采集（10 个插件 + 2 个导入入口）**

- 代码托管：GitHub（当前文件树 + **提交历史扫描**，历史层残留泄露语义）、Gitee；
- Wiki：MediaWiki 兼容适配器（recentchanges 增量游标，任意 MediaWiki 站点可用）；
- 知识分享：博客园 RSS、Stack Overflow API、通用 RSS/Atom/Sitemap/URL（任何有订阅源的站点）；
- 容器镜像：OCI Distribution API（Docker Hub 实测，ghcr/阿里云同协议），含 **whiteout/opaque 层语义**——被删除的层里的历史凭据仍会被检出；
- App：Android APK（assets/dex 字符串/manifest，三种入口：上传/本地/公开下载 URL 监控）；
- 小程序：未加密 wxapkg 容器解析（加密包合规拒绝）；
- 导入（不计入渠道数）：本地目录、Git 仓库副本、压缩包（zip/tar，防穿越/防炸弹）。

**② 检测（自研引擎，43 条规则）**

管线七步：前缀/正则匹配 → 占位符与已知示例过滤 → 香农熵过滤 → 上下文正则（命中行±N 行内的服务域名/变量名）→ 格式感知（.env/YAML/JSON/INI 键值、数据库连接 URL、GCP 服务账号 JSON）→ 有边界 Base64 解码（深度≤2）→ AK/SK 配对加成（同文件行距≤阈值，双向 boost 置信度）→ 跨规则重叠消解 → 置信度分级（high≥80 / medium≥50 / low）。

**③ 入库与去重（三层闸门）**

- 内容级：`(source_id, version_id, path, content_hash)` 唯一——不变的内容整项跳过；
- 凭据级：HMAC-SHA256 指纹（主密钥派生 pepper，不可反推）——同一凭据只一条记录；
- 位置级：`location_hash = sha256(平台|URL|仓库|路径|版本|行号|内容哈希)` 唯一——同一位置重复出现只更新 last_seen。

**④ 人工复核**

候选 → 确认 / 误报 / 忽略 / 恢复，全部写 ReviewLog 留痕；"真实但失效"与"误报"是两个不同结论；忽略规则有四类作用域（规则/路径通配/指纹前缀/渠道类别）且命中=标记不删除。

**⑤ 最小化验证（默认关闭）**

8 个验证器（GitHub PAT / AWS STS 配对 / Gitee / GitLab / Slack / Telegram / npm / Hugging Face），只调"我是谁"类固定端点；`follow_redirects=False` 且校验最终域名；证据只存端点与状态码，响应体永不入库；11 态状态机区分"失效"与"无法判断"（401=invalid、403 分语义、限流/网络故障不算 invalid）；单条/批量/可选自动三种入口统一队列，每次验证追加历史。

**⑥ 展示与导出**

Vue3+Element Plus 全中文六页（总览/监控任务/发现/验证中心/渠道与规则/设置）；默认脱敏（如 `ghp_4****kL2b`），reveal 需显式操作并留审计；CSV/JSON 流式导出，CSV 防公式注入（=+-@ 前缀转义），默认脱敏导出。

### 2.3 合规边界（全项目硬约束，接手者必读）

1. 只做"公开泄露的发现 + 记录 + 最小化有效性验证"，**绝不利用凭据执行业务操作**（不读数据、不枚举资源、不写操作、不试用计费）；
2. 在线验证默认关闭；检测阶段**禁用任何第三方引擎自带的在线验证**；
3. 无合规公开接口的渠道（微博）**如实标 blocked，不做绕过**；加密小程序包**拒绝解密**（V1MMWX 格式检测到即停止）；
4. 不引入绕过平台访问控制的能力；验证器禁止把采集到的内容地址当作验证目标；
5. 禁止把采集到的凭据发送到与其所属服务无关的第三方。

## 三、开发意义

### 3.1 赛题回应（每项要求 → 具体数字 → 证据）

| 赛题要求 | 回应 | 证据位置 |
| --- | --- | --- |
| 7 类公开渠道全部建设 | 7 类全部有明确结论：5 类有实现（含 7 个平台 live_verified），微博 blocked（有调研依据），小程序仅未加密包（合规边界） | docs/SUPPORT_MATRIX §二 |
| 尽可能多的凭据类型 | **43 类可检测**（规则全带正反样例）、8 类可最小验证 | docs/SUPPORT_MATRIX §三 |
| 分钟级发现 | 受控实验 **P50=25.5 秒 / P95=26.9 秒**（秒级达成） | docs/EVALUATION §4.3 |
| 易于新增渠道 | 三插件契约；**单日新增 6 个采集器 + 8 个验证器**的实证 | docs/EXTENSIBILITY §四 |
| 四件套交付 | 全部齐备且数字相互一致 | docs/DELIVERABLES §一 |

### 3.2 技术工程价值

1. **插件化架构的完整可复现样本**：三条契约（Collector/Rule/Verifier）+ 框架公共设施（预算/限流/游标/去重/入库/展示）的职责切分干净到"新增渠道零框架改动"；且开发中 5 个框架级缺陷都是在扩展过程中暴露并加固的——证明架构在真实压力下工作。
2. **合规工程的可复制范式**：每个"不能做"都有书面结论与理由（如 [OI] 判 unsupported 是因为没有"不枚举资源"的端点），这套"边界即文档"的纪律对任何安全工具/爬虫类项目都有直接参考价值。
3. **数据建模亮点**：指纹/位置双层去重 + 七类时间字段 + published_confidence 可信度体系——"诚实的口径"是这个项目区别于演示级作品的核心资产。
4. **测试策略示范**：平台响应用 httpx.MockTransport 注入（离线可重复），live 验证独立脚本不污染测试；"样例即测试即文档"（每条规则的正反样例同时是回归用例）。

### 3.3 现实应用价值

- **个人自查**：把自己 GitHub 用户名/组织/博客 feed 填进监控任务，即可持续盯自己的公开面是否泄密；
- **企业巡检**：监控与自身相关的组织名/关键词/官方镜像仓库，发现即告警台账；
- **安全教学**：完整可复现的检测管线 + 受控实验数据（20 凭据/21 位置/14 类型），适合做安全工程课程案例；
- **低门槛**：零配置可跑（`uvicorn app.main:app` 一条命令），中文界面，SQLite 免部署。

## 五、名词表

| 名词 | 含义 |
| --- | --- |
| CCS | Cloud Credential Sentinel，本系统代号 |
| ContentItem | 采集器输出的标准内容单元（平台元数据+文本+版本+时间信息+extra） |
| Collector / Rule / Verifier | 三个插件契约：采集器（Python 类）/ 凭据规则（YAML 条目）/ 验证器（Python 类） |
| 凭据指纹 | HMAC-SHA256(主密钥派生 pepper, 类型+规范化值+配对字段)，凭据级去重键，不可反推 |
| location_hash | sha256(平台|URL|仓库|路径|版本|行号|内容哈希)，位置级去重键 |
| published_confidence | 公开时间可信度：none/low/medium/high；只有 medium/high 参与时延统计 |
| live_verified | 状态口径：真实公网渠道实采验证通过（另有 planned/implemented/offline_tested/blocked 四级） |
| whiteout / in_final_view | 容器镜像层删除标记 / "当前容器视图可见"标记；历史层残留凭据照样检出 |
| rccontinue | MediaWiki recentchanges 增量游标参数 |
| SigV4 | AWS 请求签名协议；本项目 stdlib 自实现最小版，仅用于 STS GetCallerIdentity |
| wxapkg / V1MMWX | 微信小程序包格式 / 加密包标识；加密包明确拒绝解密 |
