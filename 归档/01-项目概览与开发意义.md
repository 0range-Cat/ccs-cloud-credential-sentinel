# 01 · 项目概览与开发意义

> 归档时间：2026-10-08。本文回答三个问题：这是什么项目、为什么做、它有什么价值。

## 一、项目是什么

**项目名称**：云上凭据泄露自动化检测与响应系统（CCS，Cloud Credential Sentinel）

**项目来源**：网络安全创新大赛赛题——"云上凭据泄露的自动化检测"。

**一句话定义**：一个单机可持续运行的中文 Web 平台，持续监控公开互联网渠道（代码托管、Wiki、知识分享社区、容器镜像仓库、App 产物等），自动发现其中意外泄露的云平台/服务凭据（API Key、AccessKey、Token、私钥等），记录、去重、供人工复核，并可在默认关闭的前提下做严格最小化的在线有效性验证。

### 解决的真实问题

开发者和运维人员经常把 API Key、云厂商 AK/SK、数据库口令、私钥等敏感凭据写进代码、配置文件、博客文章，并无意中推送到公开渠道。攻击者通过搜索这些公开渠道即可获取凭据直接利用（异常扣费、数据泄露、资源滥用）。本项目做的就是**攻击者视角的自动化巡查，站在防守方一侧**：

- **发现**：对公开渠道做持续、增量、合规的采集与正则+上下文检测；
- **记录**：完整时间模型（何时公开/何时抓取/何时发现/首次与最近出现），可统计"发现时延"；
- **响应辅助**：人工复核分级 + 可选的"这条密钥现在还有效吗"最小验证，帮助确认危害等级。

### 明确不做的事（合规边界，全项目贯穿）

- 只做"公开泄露的发现 + 记录 + 最小化有效性验证"，**绝不利用凭据执行任何业务操作**（不读数据、不枚举资源、不写操作）；
- 在线验证**默认关闭**，且仅使用各平台官方文档明确的最小认证接口（如 GitHub `GET /user`）；
- 检测阶段**禁用任何第三方引擎自带的在线验证**（这也是不引入 TruffleHog 运行链路的原因之一）；
- 无合规公开接口的渠道（如微博）**如实标注 blocked，不做绕过**；加密小程序包**拒绝解密**；
- 不引入绕过平台访问控制的能力。

## 二、开发意义

### 1. 赛题与交付层面

赛题要求：多公开渠道检索泄露凭据、支持尽可能多的凭据类型、分钟级发现、易于新增渠道，并交付源码/技术说明书/渠道列表/类型列表。本项目对每一项都有**可核查的量化回应**（见 03 号文档）：

- 赛题 7 类公开渠道全部给出明确结论（5 类有实现，2 类合规受限如实标注）；
- 43 类凭据可检测、8 类可最小验证；
- 受控实验测得发现时延 P50=25.5 秒（远优于"分钟级"）；
- 新增一个渠道 = 实现一个 Python 类，实证单日新增 6 个采集器。

### 2. 技术与工程层面

- **插件化架构的完整实践**：Collector（采集）/ Rule（YAML 规则）/ Verifier（验证）三条插件契约，框架承担预算、限流、游标、去重、入库、展示等全部公共逻辑；
- **合规工程的可复制范式**：每个"能力边界"都有书面结论与理由（如 [OI]/Anthropic/Stripe 判 unsupported 是因为没有"不枚举资源"的合规端点），这套口径纪律对任何安全工具开发都有参考价值；
- **数据建模亮点**：凭据实体（HMAC 指纹）与出现位置（location_hash）分离建模；七类时间字段分离且"无证据的公开时间显示未知"，杜绝用抓取时间冒充公开时间——这是多数同类开源工具没有做到的诚实口径。

### 3. 现实应用层面

可服务于：个人开发者自查（自己的代码/仓库是否泄过密）、企业安全巡检（监控与自身相关的关键词/组织）、安全研究与教学（完整可复现的检测管线与实验数据）。界面为全中文单用户设计，部署门槛低（零配置可跑）。

## 三、核心特性一览

| 能力域 | 特性 |
| --- | --- |
| 采集 | 10 个插件化采集器 + 2 个导入入口；游标/条件请求/版本缓存三级增量；预算与限流内建（max_items/max_bytes/max_seconds、429+Retry-After 优雅停止） |
| 检测 | 自研引擎：43 条 YAML 规则 + 占位符/熵/上下文/格式感知/Base64 解码/AK-SK 配对；置信度分级（high≥80/medium≥50/low）；每条规则带正反样例自检 |
| 去重 | 凭据指纹（HMAC-SHA256+主密钥 pepper）与位置哈希双层去重；同凭据多位置关联；重复扫描只更新 last_seen |
| 时间模型 | source_published_at（必须带证据与可信度）/ fetched_at / detected_at / first_seen_at / last_seen_at / verified_at 分离；未知显示"未知" |
| 验证 | 独立模块默认关闭；8 个最小验证器；11 态验证状态机（401/403 不一律判 invalid；限流/网络故障不算 invalid）；每次验证追加历史 |
| 安全 | 凭据原文与平台 Token Fernet 加密；界面默认脱敏；reveal 留审计；CSV 导出防公式注入；日志零凭据 |
| 界面 | Vue3 + Element Plus 全中文六页：总览/监控任务/发现/验证中心/渠道与规则/设置 |
| 调度 | APScheduler 心跳 + 数据库任务声明；重启自动恢复（running→interrupted）；同任务防并行 |

## 四、名词表（接手者速查）

| 名词 | 含义 |
| --- | --- |
| CCS | 本系统代号 Cloud Credential Sentinel |
| Collector | 采集器插件，产出 ContentItem（平台元数据+内容+版本+时间信息），不接触数据库 |
| Verifier | 验证器插件，只做最小认证判断；固定端点、禁重定向、证据不含响应体 |
| ContentItem | 采集器输出的标准内容单元 |
| 凭据指纹 | HMAC-SHA256(主密钥派生 pepper, 类型+规范化值)，用于凭据级去重，不可对外反推 |
| location_hash | sha256(category\|platform\|origin_url\|path\|version_id\|line\|content_hash)，位置级去重 |
| live_verified | 状态口径：真实公网渠道实采验证通过（区别于 offline_tested / implemented / planned / blocked） |
| whiteout | 容器镜像层删除标记；本项目区分"当前视图可见"与"历史层残留"，历史凭据仍会被检出 |
| wxapkg | 微信小程序包格式；仅解析未加密包，加密包（V1MMWX）合规拒绝 |
