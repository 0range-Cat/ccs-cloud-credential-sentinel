## 一、四种部署路径对照与步骤

### 1.1 Windows 原生 ✅ 实测（开发机日常路径）

```
前置：Python 3.11+（实测 3.13.9）、Node 18+（实测 24，仅构建前端需要）
cd backend
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env        （可选）
.venv\Scripts\uvicorn app.main:app --host 127.0.0.1 --port 8000
```

前端构建一次（改动前端后必须重跑——**常驻进程会继续托管旧 dist**）：

```
cd frontend && npm install && npm run build
```

实测记录（2026-09-19，docs/DEPLOYMENT §1）：uvicorn 启动 → /api/system/info 正常；导入样例 16 凭据/17 位置；重复扫描幂等；页面正常打开。

### 1.2 Ubuntu 原生 ⚠️ 步骤齐备未重复实测（Linux 路径已被 Docker 覆盖）

完整步骤含 systemd 单元模板，见 docs/DEPLOYMENT.md §2（apt 装依赖 → venv → pip → alembic → 前端构建 → systemd 服务 → 环境变量）。**Linux 运行路径已由 Docker（容器即 Linux）实测覆盖**；接手者若有服务器可按步骤实测后回填证据。

### 1.3 Docker Compose ✅ 实测（2026-09-19，Windows Docker Desktop 29.7.2）

```bash
docker compose up -d --build
# http://127.0.0.1:8000（默认仅绑定回环）
docker compose logs -f app
```

- Dockerfile 多阶段：node:22-alpine 构建前端 → python:3.12-slim 运行时；**容器启动自动执行 Alembic 迁移**；
- docker-compose.yml：端口 `127.0.0.1:8000:8000`（远程部署改反代/加令牌后再暴露）；数据卷 `./data:/app/data`；环境变量 CCS_ACCESS_TOKEN/CCS_WORKERS 可注入；
- 实测：构建成功；容器内 /api/system/info → 35 规则/10 采集器/8 验证器；UI 托管与统计正常；测试后容器已停止清理。

### 1.4 PostgreSQL 模式 ✅ 实测（Docker PG16-alpine 一次性容器）

- 设置 `CCS_DB_URL=postgresql+psycopg://...`；
- 实测内容（2026-09-19，DEVLOG）：Alembic 迁移**直跑 PG** 成功；核心流程（采集 7 项 → 检测 17 候选 → 16 凭据/17 位置 → 二次扫描幂等 0 新增 → 统计）全通过；
- 依赖 `psycopg[binary]==3.3.6` 已锁定；印证 D2 决策"换 PostgreSQL 仅改连接串"。

## 二、远程访问安全（必读）

1. 默认绑定 127.0.0.1；远程部署二选一：
   - **Nginx 反向代理 + Basic Auth/TLS**，仅暴露 443；
   - **CCS_ACCESS_TOKEN** 环境变量启用内置单用户口令：POST /api/login 换发 cookie（httponly）/Bearer 双通道；
2. **不要把 8000 端口直接暴露公网**（无 TLS 且登录未做限速）；
3. docker-compose.yml 端口映射默认回环；改公网前先完成上述二选一。

## 三、备份、恢复与迁移

| 数据 | 备份要求 | 恢复要点 |
| --- | --- | --- |
| data/app.db（SQLite WAL） | 常规备份（WAL 模式下建议停写后拷贝三件套 db/-wal/-shm） | 三件套一起恢复 |
| **data/master.key** | **必须与数据库同时备份** | 丢失=全部凭据密文永久不可解；恢复时与库成对出现 |
| data/latency_log.json、publish_log.json | 评价 4/5 原始证据（gitignored） | 需保留实验证据时一并备份 |
| data/cache/、data/tmp/ | 可清理（retention.cache_days 默认 30；tmp 有配额与过期清理） | 不需备份 |
| PostgreSQL 模式 | 随所选托管策略 | 主密钥仍单独备份 |

换机器迁移清单：①库+主密钥成对迁移 ②.env/环境变量（CCS_ACCESS_TOKEN 等）③前端 dist（或重新构建）④启动后核对 /api/system/info 与任务自动重排（running→interrupted→pending 属正常）。

## 四、环境事实（勿重复踩坑——全部为开发过程实测沉淀）

### 4.1 本机与网络

| 事实 | 影响 |
| --- | --- |
| api.github.com 匿名 403 = 共享出口 IP 配额耗尽（认证态 4999/5000 正常） | 403 ≠ 被封锁；配置 Token 即可，勿误判环境 |
| raw.githubusercontent.com 200（匿名亦通） | 可作为备用内容通道 |
| Git Bash curl 发中文 JSON body 会 GBK 乱码 | 用 Python 客户端或界面操作替代 |
| 后台子智能体并发上限 1 个（开发环境） | 调研/派单串行编排 |
| 本机直连 github.com 443 可能被重置；本地代理端口 7897（Clash 系）可用 | 推送用 `git -c http.proxy=http://127.0.0.1:7897 -c https.proxy=...` 一次性代理，不写全局配置（2026-10-08 归档推送实测） |

### 4.2 平台行为（采集与实验）

| 事实 | 处置（已在代码固化） |
| --- | --- |
| 维基媒体拒通用 UA（curl 200 但 httpx 默认 UA 403） | 统一合规 UA `ccs-collector/0.1 (https://localhost; contact: admin@example.com)`（D10） |
| MediaWiki formatversion=2 修订对象**无 revid 字段** | 按 pageid 映射（有测试锁定） |
| Stack Overflow `quota_remaining:0` 被 `x or 1` 吞（falsy 陷阱） | 显式判 None（有测试） |
| Gitee 匿名限流随共享 IP 波动，随时可能 403 | rate_limited 优雅停止语义；生产配 Token |
| Docker Hub blob **307 → CDN** | 采集层 follow_redirects=True；**验证器仍严格禁重定向**（两模块语义不同，勿统一） |
| GitHub fine-grained PAT 默认无 Contents:write（PUT contents 403） | 受控实验需追加该权限 |
| GitHub push protection 拦格式逼真合成凭据（实测拦 Twilio SID；ghp_ 假值因校验位反而不拦） | 官方 bypass API（reason=used_in_tests）流程固化于 latency_experiment.py |
| ghcr.io 匿名 token DENIED（疑似环境特异性） | 待复核（RESEARCH 待核实 #4）；Docker Hub/阿里云同协议已通 |

### 4.3 构建与代码

| 事实 | 处置 |
| --- | --- |
| alembic.ini 含中文注释在 GBK 控制台触发 UnicodeDecodeError | 保持纯 ASCII |
| 改包先重编：前端改动后旧 dist 仍被常驻进程托管 | npm run build 后重启 uvicorn/重建容器 |
| Windows zoneinfo 需 tzdata 包 | requirements 已锁 |
| pytest 基线命令（Git Bash） | `cd backend && .venv/Scripts/python -m pytest`（直接取末行 passed 汇总，勿经 grep 管道——输出缓冲差异会吞结果行，2026-10-08 实测） |
| API 事件循环内不能直接 asyncio.run | 已由 pipeline._run_async 线程适配固化（勿拆） |

## 八、封存/重启/恢复运维清单

1. **封存**：`docker compose down`（保留 ./data 卷）或停 uvicorn；备份 数据库+主密钥（+实验证据文件）；
2. **恢复运行**：原生 uvicorn 启动（自动迁移+任务重排）；Docker `docker compose up -d`；
3. **重启后核查**：/api/system/info 正常；上次 running 批次已标 interrupted、任务回 pending（设计行为）；
4. **换机器**：master.key 与数据库成对迁移，否则凭据密文不可解；
5. **长期封存安全**：确认实验用 GitHub Token 已吊销（文档多处建议，最后记录 2026-09-20 已 401）；data/github.token 文件建议删除。

## 九、GitHub 归档推送记录（2026-10-08，供复现）

- 远程：`origin = https://github.com/0range-Cat/ccs-cloud-credential-sentinel.git`（公开仓库，2026-10-08 经官方 API `POST /user/repos` 创建——本机 git credential 凭据复用）；
- 网络：直连 443 被重置 → 一次性代理端口 7897 推送（`git -c http.proxy=... -c https.proxy=...`，未写全局配置）；
- **push protection 拦截处理**：规则 YAML 中 10 处合成正例样例值被 GitHub 误判为真实密钥（AWS_KEYID/AWS_SECRET/OPENAI×2/GITLAB/MAILGUN/NOTION/STRIPE×2/TWILIO/SLACK）→ 全部走官方 `POST /repos/{o}/{r}/secret-scanning/push-protection-bypasses`（reason=used_in_tests，与 latency_experiment.py 固化流程一致）→ 分两批（每推一次才暴露下一批 placeholder ID）→ 全部 200 → 推送成功。bypass 各 7 天有效期自动过期；
- 推送前安全门：`git ls-files` 无真实密钥；data/ 全 gitignored 且从未入库（`git log --all -- data/` 为空）；敏感模式正则扫描（ghp_/github_pat_/sk-ant-/AKIA/xox[brap]-/hf_/glpat-/npm_/dckr_pat_/pypi-/PEM 头）对归档/memory/文案零命中；tracked 命中项逐个核实均为规则 tests 样例或文档示例（合成假值）。
