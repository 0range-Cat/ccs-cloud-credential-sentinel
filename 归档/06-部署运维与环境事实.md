# 06 · 部署运维与环境事实

> 归档时间：2026-10-08。本文汇总四种部署路径的实测状态、运维要点，以及开发过程中沉淀的"勿重复踩坑"环境事实（原 HANDOFF.md 环境事实节的扩编）。

## 一、四种部署路径对照

| 路径 | 实测状态 | 适用场景 | 关键步骤 |
| --- | --- | --- | --- |
| Windows 原生 | ✅ 实测（开发机日常路径） | 开发/单机使用 | venv + pip install + uvicorn；前端 npm run build 一次 |
| Docker Compose | ✅ 实测（构建+容器运行验证，2026-09-19） | 快速部署/交付演示 | `docker compose up -d --build`；多阶段镜像（node:22-alpine 前端构建 → python:3.12-slim 运行时），启动自动 Alembic 迁移 |
| PostgreSQL 模式 | ✅ 实测（Docker PG16-alpine 一次性容器冒烟：迁移+核心流程+幂等） | 数据量上量/多库 | 依赖 psycopg[binary]==3.3.6 已锁；仅需改连接串 |
| Ubuntu 原生 | ⚠️ 步骤齐备未重复实测（Linux 路径已由 Docker 覆盖） | 云服务器 | 完整 systemd 单元模板见 docs/DEPLOYMENT.md §2；有服务器可补实测 |

## 二、远程访问安全（必读）

1. 默认绑定 `127.0.0.1`——远程部署二选一：
   - Nginx 反向代理 + Basic Auth/TLS，仅暴露 443；
   - `CCS_ACCESS_TOKEN` 环境变量启用内置单用户口令（POST /api/login，cookie 会话）。
2. **不要把 8000 端口直接暴露公网**（无 TLS 且界面未做登录限速）；
3. docker-compose.yml 端口映射默认 `127.0.0.1:8000:8000`，远程部署改为反代/加令牌后再暴露。

## 三、备份与恢复

- **`data/master.key` 与 `data/app.db` 必须一起备份**——主密钥丢失 = 所有凭据密文永久不可解；
- Docker 部署：数据在 `./data` 卷，随卷持久化；重建容器不丢数据，但删卷会丢；
- 实验数据 `data/latency_log.json`、`data/publish_log.json`（gitignored）是评价 4/5 的原始证据，若需保留实验证据请一并备份。

## 四、环境事实（勿重复踩坑——开发过程实测沉淀）

### 4.1 本机/网络

- 后台子智能体并发上限 1 个（原开发环境限制）；
- Git Bash curl 发中文 JSON body 会 GBK 乱码——用 Python 客户端或界面操作；
- 开发网络 `api.github.com` 匿名 403 = 共享出口 IP 配额限制，**不是代码问题**；认证态正常（5000 次/时）。

### 4.2 平台行为

- **维基媒体拒绝通用 UA**（403）；采集器统一 UA：`ccs-collector/0.1 (https://localhost; contact: admin@example.com)`；
- MediaWiki `formatversion=2` 修订对象**无 revid 字段**，按 pageid 映射；
- Stack Overflow `quota_remaining:0` 判断勿写 `x or 1`（falsy 陷阱）；
- Gitee 匿名限流随共享 IP 波动：实采可行但随时可能 403 → 已验证优雅停止；
- Docker Hub blob 会 307 到 CDN：**采集层**需 follow_redirects=True（验证器仍严格禁重定向——两个模块语义不同，勿"统一"）；
- GitHub push protection 会拦截格式逼真的合成凭据（实测拦 Twilio SID）→ 官方 bypass API（reason=used_in_tests）流程已固化进 latency_experiment.py；
- `ghp_` 假值不触发 push protection（GitHub 对自家 PAT 有校验位校验）；
- GitHub fine-grained PAT 默认无 Contents:write（PUT contents 403）——做受控实验需追加该权限；
- `ghcr.io` 匿名 token 调研时 DENIED（疑似环境特异性，待复核）。

### 4.3 代码/构建

- alembic.ini 保持纯 ASCII（中文注释在 GBK 控制台触发 UnicodeDecodeError）；
- **改包先重编**：前端改动后必须 `npm run build`，否则后端托管的是旧 dist；
- 常驻进程注意旧 dist/旧容器镜像（改动后重启 uvicorn/重建容器）;
- pytest 基线命令：`cd backend && .venv/Scripts/python -m pytest`（Git Bash 路径）；
- Windows 需 tzdata 包（zoneinfo 依赖，requirements 已锁）。

### 4.4 错误处置 TOP（历史真实缺陷，回归测试已锁定）

| 症状 | 根因 | 防回归 |
| --- | --- | --- |
| 验证器 TypeError | 注册的是类而非实例 | base.register 装饰器自动实例化 |
| 流水线 internal_error | BaseCollector 缺 rate_limited 默认属性 | mock 测试 |
| "发现数 0" | trigger_manual_run 先置 running 与防重叠检查冲突 | test_pipeline_dedup |
| API 内 asyncio.run 报错 | 事件循环限制 | pipeline._run_async 线程适配 |
| 真实验证路径 TypeError | worker.http_factory 返回"工厂的工厂" | 真实冒烟+回归（mock 测试未覆盖该形状的教训） |
| OCI whiteout 层序错误 | 初版最终视图顺序错 | test_artifacts 最终视图断言 |
| wxapkg 条目内容错位 | offset 相对正文起点计算错 | 测试锁定 |
| APK PK 校验笔误 | `len>4` 边界 | 测试锁定 |

## 五、监控与日志

- 应用入口 `/api/system/info`：版本、数据库、调度器状态、规则/采集器/验证器数量——健康检查首选；
- `/api/overview/stats`：统计（渠道/类型/状态/时延分布，含样本数与口径）；
- 批次级统计在 ScanRun.stats_json（items_seen/candidates/new_credentials/stop_reason）；
- 日志不打印凭据原文、完整上下文、平台 Token（设计约束，勿破坏）。

## 六、版本与依赖锁定

## 七、封存/重启运维清单

1. 服务器封存：`docker compose down`（保留 ./data 卷）或停 uvicorn 进程；备份数据+主密钥；
2. 恢复运行：原生路径 uvicorn 启动（自动迁移+恢复调度任务）；Docker 路径 `docker compose up -d`；
3. 重启后核查：/api/system/info 正常 + 重启前 running 任务被标 interrupted（设计行为）；
4. 若换了机器：先确认 `data/master.key` 已随数据库迁移，否则凭据密文无法解密。
