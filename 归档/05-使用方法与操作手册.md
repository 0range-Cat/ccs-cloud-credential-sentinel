## 一、环境要求与安装

### 1.1 环境要求

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 操作系统 | Windows / macOS / Linux | 开发实测 Windows 11；Linux 路径经 Docker 实测；Ubuntu 原生步骤齐备 |
| Python | 3.11+（实测 3.13.9） | 仅后端需要 |
| Node | 18+（实测 24） | 仅构建前端时需要；仓库已带 dist 可跳过 |
| Docker（可选） | 近期版本 | 仅容器部署需要 |
| 时区数据 | tzdata 包（requirements 已含） | Windows zoneinfo 依赖 |

### 1.2 方式 A：本机原生安装（推荐单机使用）

```bash
# ① 后端
cd backend
python -m venv .venv
.venv\Scripts\activate            # Windows；Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
# 可选: copy .env.example .env    （默认零配置可跑）
.venv\Scripts\uvicorn app.main:app --host 127.0.0.1 --port 8000
# 首次启动自动完成：Alembic 迁移 → 生成 data/master.key → 同步规则与能力清单 → 启动调度器与验证 worker
```

```bash
# ② 前端（仅首次或前端改动后；仓库已带 dist 可跳过）
cd frontend
npm install
npm run build      # 产物 frontend/dist，后端自动托管
```

- 打开 **http://127.0.0.1:8000** = 中文管理界面；
- **http://127.0.0.1:8000/docs** = 交互式 API 文档（FastAPI 自动生成）。

### 1.3 方式 B：Docker Compose

```bash
docker compose up -d --build
docker compose logs -f app
# http://127.0.0.1:8000（默认仅绑定回环）
```

多阶段镜像（node:22-alpine 构建前端 → python:3.12-slim 运行时，**容器启动自动迁移**）；数据卷 `./data:/app/data`（数据库+主密钥随卷持久化）。

### 1.4 方式 C：PostgreSQL 模式（数据量大或多实例时）

设置环境变量 `CCS_DB_URL=postgresql+psycopg://user:pass@host:5432/ccs` 即可——Alembic 迁移与全部业务代码同构（Docker PG16 已实测：迁移+采集+检测+去重+幂等+统计全通过）。

## 二、首次配置（三步）

1. **平台采集账号**（【设置】页 →"平台采集账号"）：填 GitHub Token（可选但强烈建议——匿名 60 次/时 vs 认证 5000 次/时；Gitee Token 同理）。Token 经 Fernet 加密存储，不出现在任何日志与导出。填完点【测试连接】——**该测试只用你配置的采集账号，与扫描发现的任何凭据无关**（隔离是设计约束）。
2. **网络与预算**（设置页）：network.proxy（如需）、network.rate_per_host_per_sec（默认 2.0）、scan.max_items/max_bytes/max_seconds/max_file_bytes（默认 2000 / 512MB / 1800s / 1MB，可在每个来源上覆盖）。
3. **远程访问保护**（仅远程部署）：设 `CCS_ACCESS_TOKEN` 环境变量 → 登录接口 POST /api/login 换发 cookie（httponly）/Bearer 双通道；或前置 Nginx 反代+TLS。**勿把 8000 直接暴露公网**（无 TLS 且登录未做限速）。

## 三、日常操作：六个页面逐一说明

### 3.1 总览（Overview）

一屏看全：命中次数/去重凭据数/唯一位置数/疑似候选/人工确认/验证分布（valid·invalid·无法判断）；凭据类型 Top 与平台分布；**发现时延卡（P50/P95 附样本数与口径说明——只统计公开时间可信度 medium/high 的样本，未知公开时间不参与，绝不冒充）**；最近扫描批次列表（含 stop_reason）。

### 3.2 监控任务（Tasks）

- **新建来源**：选采集器（GitHub/Gitee/MediaWiki/RSS·Sitemap·URL/Stack Overflow/容器镜像/APK/wxapkg/本地目录/压缩包）→ 填种子（仓库地址/组织/关键词/URL/路径）→ 配 include/exclude 通配与预算 → 模式选"手动"或"持续监控"（interval_sec 建议 120~600）；
- **立即运行**：手动触发一次扫描；批次抽屉看实时统计（items_seen/skipped/candidates/new_credentials/stop_reason——rate_limited 表示限流优雅停止而非故障）；
- **任务操作**：暂停/恢复/取消/重试；查看历史批次；
- **种子发现**（批量建任务）：填 GitHub/Gitee 组织名 → 自动拉公开仓库列表生成多个来源任务（orgs→users 回退、限量、失败原因写入 notes）。

### 3.3 发现（Findings）

- 列表默认**脱敏**（`ghp_4****kL2b`）；筛选：关键词/类型/复核状态/验证状态/平台/分页；
- 详情抽屉：全部出现位置（平台/URL/仓库/路径/行号/版本）+ **脱敏上下文** + 证据（命中规则、配对信息、是否 Base64 解码）+ 时间线（公开时间未知如实显示"未知"）+ 验证历史 + 审计记录；
- 【显式查看原文】（reveal）：需显式点击，返回原文并**写 reveal_access 审计**；
- 复核：确认 / 误报 / 忽略 / 恢复（单个或批量）；"真实但失效"与"误报"是两个不同结论，分别用 invalid 验证结果与 false_positive 复核表达；
- 提交验证：单条或勾选批量（默认关闭自动验证；无验证器类型不入队，直接 unsupported）；
- 导出：CSV/JSON（带当前筛选；默认 masked=true 脱敏，显式选择才导原文；CSV 已防公式注入）。

### 3.4 验证中心（Verification）

验证器清单（8 个及其 supported_types）+ 队列（queued/running）+ 追加式历史（每次验证一条，不覆盖）。**验证结果解读表**：

| 状态 | 含义 | 处置建议 |
| --- | --- | --- |
| valid | 平台确认凭据当前有效 | 高危，立即通知轮换 |
| invalid | 认证失败（401 类） | 已失效/已吊销，可降级处理 |
| inconclusive | 无法判断（403 权限不足等） | 勿当 invalid；人工核查 |
| rate_limited / network_error | 平台限流/网络故障 | **不代表失效**；等待自动重试或手动重验 |
| missing_context | 缺配对字段等（如 AWS 缺 SK） | 补上下文后再验 |
| unsupported | 该类型无合规验证器 | 检测能力保留，人工处置 |

### 3.5 渠道与规则（ChannelsRules）

- 能力矩阵：全部采集器/验证器/渠道的实时状态（live_verified/offline_tested/planned/blocked 可见，含 blocked 原因）；
- 规则管理：43 条规则逐条启停（PATCH /rules/{id}），状态跨重启保留。

### 3.6 设置（Settings）

采集账号（加密）/ 网络与并发 / 扫描预算 / 验证策略（auto_enabled 默认关；concurrency/reverify_days/max_per_minute）/ 脱敏与导出默认 / 显示时区 / 缓存保留天数 / 连接测试 / 三种本地导入入口（目录/git-local/压缩包上传）。

## 四、演示路径（给新接手者/评审的完整走查）

### 4.1 离线演示（不依赖外网，10 分钟）

1. 启动系统 →【监控任务】→【新建来源】→ 采集器选"本地目录"，路径指向 `examples/demo_repo/`；
2. 【立即运行】→ 批次显示 items_seen=7、candidates=17、**new_credentials=16、new_occurrences=17**；
3. 【发现列表】核对四件事：约 16 条候选全脱敏；GitHub PAT 样例关联 **2 个位置**（多位置关联）；Twilio SID+AuthToken 配对加成（55→75 / 60→80）；数据库连接串弱口令被拒（反例生效）；
4. **幂等演示**：再跑一次同来源 → items_skipped=7、新增 0（版本缓存生效）；
5. 【发现】→ 挑一条【验证】→ 合成假凭据返回 invalid（401）——顺带演示"验证历史追加"；
6. 【渠道与规则】页展示能力矩阵与规则开关。

### 4.2 在线演示（GitHub 真实渠道，15 分钟）

1. 在自己公开仓库放入 `examples/demo_repo/` 文件并提交推送（全部合成假值、文件头已注明；**切勿替换为真实凭据**）；
2. 【设置】配 GitHub Token（只读即可）→【测试连接】；
3. 新建来源：采集器 GitHub、仓库 `yourname/ccs-demo` → 立即运行 → 发现列表出现对应候选；
4. 改"持续监控"（间隔 120s）→ 向仓库追加新文件 → 观察分钟级自动发现与发现列表去重；
5. （可选）演示提交历史扫描：删除已提交的"泄露"文件再扫描——历史提交中的凭据仍可检出（历史层残留语义）。

### 4.3 完整时延实验（复现评价 4/5 数字）

`scripts/latency_experiment.py`：向指定仓库推送合成凭据并自动轮询测量 T0→T1。要求 GitHub Token 含 Contents:write；遇到 push protection 拦截会自动走官方 bypass API（reason=used_in_tests）。原始数据 data/latency_log.json。历史结果：20 凭据/21 位置/14 类型，P50=25.5s/P95=26.9s。

## 五、数据管理与备份

| 路径 | 内容 | 备份要求 |
| --- | --- | --- |
| `data/app.db`（+-wal/-shm） | 业务数据库（SQLite WAL） | 常规备份 |
| `data/master.key` | 主密钥（Fernet 派生源） | **必须与数据库同时备份**——丢失=所有凭据密文永久不可解 |
| `data/github.token` | 开发期本地 Token 文件（gitignored） | 敏感；归档后应随吊销一并清理 |
| `data/latency_log.json` / `publish_log.json` | 时延实验原始证据 | 若需保留证据请一并备份 |
| `data/cache/` `data/tmp/` | 原始内容副本（retention.cache_days 默认 30）/ 解包临时区 | 可清理，有配额与过期清理 |

- 换机器迁移：数据库+主密钥成对迁移；只迁其一等于数据报废；
- PostgreSQL 模式：备份策略随所选托管；主密钥仍需单独备份。

## 六、FAQ（现象 → 原因与处置）

| 现象 | 原因与处置 |
| --- | --- |
| GitHub 匿名扫描 403 | 共享出口 IP 匿名配额耗尽（非故障）；配置 Token 即可（认证 5000 次/时） |
| Gitee 扫描中途停止，stop_reason=rate_limited | 匿名限流触发；系统按 Retry-After 优雅停止（这是正常语义）；生产配 Gitee Token |
| 维基百科 403 | 已内置合规 UA；自建站点请检查站点 UA 策略 |
| MediaWiki 扫描 0 条 | 检查 recentchanges 可见性/命名空间配置；历史教训（UA 与 pageid 映射）已在代码修复 |
| 验证结果 network_error | 网络故障，**不判无效**；稍后重试或等自动重试 |
| 验证结果 inconclusive | 403 权限不足等无法判断情形；人工核查，勿当 invalid |
| 列表看不到原文 | 设计如此（默认脱敏）；需显式 reveal（会留审计） |
| 验证按钮没有反应/类型不支持 | 该类型无合规验证器 → 状态直接 unsupported；检测能力保留 |
| 端口 8000 打不开 | 后端未启动；或前端未构建（直接用仓库自带 dist）；或端口被占（换 --port） |
| Docker 内数据丢失 | 检查 ./data 卷挂载；master.key 必须与数据库同卷保留 |
| 重启后任务状态异常 | 重启恢复会把 running 批次标 interrupted、任务回 pending——这是设计行为，任务会自动重排 |
| 时延统计一直 0 样本 | 正常：只有公开时间可信度 medium/high 的来源（如 MediaWiki 修订）参与统计 |

## 八、卸载/清空

1. 停止 uvicorn / `docker compose down`；
2. 删除 `data/` 目录（数据库+主密钥+缓存全部清除；如含实验证据先另行备份）；
3. Docker 场景另删镜像 `ccs:latest`。
