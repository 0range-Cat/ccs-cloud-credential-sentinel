# 05 · 使用方法与操作手册

> 归档时间：2026-10-08。本文面向实际使用者：从零启动 → 日常操作 → 演示路径 → 数据管理。权威部署文档 `docs/DEPLOYMENT.md`，演示指南 `docs/DEMO.md`，本手册是整合版。

## 一、环境要求

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 操作系统 | Windows / macOS / Linux 均可 | 开发实测 Windows 11；Linux 路径经 Docker 实测 |
| Python | 3.11+（实测 3.13.9） | 仅后端 |
| Node | 18+（实测 24） | 仅构建前端时需要；已有 dist 可跳过 |
| Docker（可选） | 任意近期版本 | 用容器部署才需要 |
| 网络 | 能访问目标公开渠道 | 某些内网/共享出口可能触发平台限流 |

## 二、安装与启动（三分钟版）

### 方式 A：本机原生（开发/单机推荐）

```bash
# 1. 后端
cd backend
python -m venv .venv
.venv\Scripts\activate            # Windows；Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
# 可选: copy .env.example .env    （默认零配置可跑）
uvicorn app.main:app --host 127.0.0.1 --port 8000
# 首次启动会自动执行数据库迁移并生成 data/master.key
```

```bash
# 2. 前端（仅首次或前端改动后；仓库已带 dist 可跳过）
cd frontend
npm install
npm run build                     # 产物 frontend/dist 由后端自动托管
```

打开 **http://127.0.0.1:8000** 即中文管理界面；API 文档在 **http://127.0.0.1:8000/docs**。

### 方式 B：Docker Compose

```bash
docker compose up -d --build
docker compose logs -f app
# 打开 http://127.0.0.1:8000（默认仅绑定回环）
```

数据卷 `./data:/app/data`（数据库+主密钥随卷持久化）。

## 三、首次配置

1. **平台采集账号（设置页）**：填 GitHub Token（可选但强烈建议——匿名限流 60 次/时，认证 5000 次/时）。Token 经 Fernet 加密存储，不出现在日志与导出。填完点【测试连接】（该测试只用你配置的账号，与扫描发现的任何凭据无关）。
2. **远程访问保护（仅远程部署时）**：设置环境变量 `CCS_ACCESS_TOKEN` 启用单用户口令（登录接口 POST /api/login），或前置 Nginx 反代+TLS。**不要把 8000 直接暴露公网**。

## 四、日常操作流程

### 4.1 创建监控任务（核心流程）

1. 界面 →【监控任务】→【新建来源】：
   - 采集器：GitHub 仓库扫描 / Gitee / MediaWiki / RSS·Sitemap·URL / Stack Overflow / 容器镜像 / APK / wxapkg / 本地目录 / 压缩包上传；
   - 填写仓库地址 / 组织 / 关键词 / URL / 目录路径等种子；
   - 模式：先"手动"验证链路，再改"持续监控"（间隔建议 120~600 秒）。
2. 点【立即运行】→ 状态实时可见（批次统计：items_seen / candidates / new_credentials / stop_reason）。

### 4.2 查看与复核发现

- 【发现列表】：默认**脱敏**显示（如 `ghp_4****kL2b`）；可按类型/复核状态/验证状态/渠道筛选；
- 点开详情：全部出现位置 + 脱敏上下文 + 证据 + 时间线（公开时间未知会如实显示"未知"）；
- 【显式查看原文】（reveal）：需显式点击并**留审计记录**；
- 复核动作：确认 / 误报 / 忽略 / 恢复——全部留痕；"真实但失效"与"误报"是不同结论。

### 4.3 有效性验证（默认关闭）

- 单条验证：发现详情 →【验证】；批量：列表勾选 → 批量验证；
- 自动验证策略：设置页开启（开启后未验证→入队、超期→重验、瞬态失败→重试）；
- 【验证中心】看队列与历史；每次验证**追加**历史不覆盖；
- 状态解读：`valid`=确认有效（高危）；`invalid`=已被吊销/错误；`inconclusive`=无法判断（如 403 权限不足）；`rate_limited`/`network_error`=平台限流或网络问题，**不代表失效**；`unsupported`=该类型无合规验证器（检测能力保留）。

### 4.4 导出

- 【设置/发现页】导出 CSV/JSON（带筛选）；默认 `masked=true`（脱敏），显式选择才输出原文；CSV 已防公式注入。

### 4.5 渠道与规则

- 【渠道与规则】页：全部采集器/验证器/规则的实时能力矩阵（live_verified/blocked/planned 可见）；
- 规则可单独启用/停用；新增规则=往 `backend/app/detection/rules/` 加一个 YAML 条目（含正反样例，注册表自检即回归）。

## 五、演示路径（给新接手者/评审的 15 分钟走查）

**离线演示（不依赖外网）**：

1. 启动系统 →【监控任务】→ 新建来源 → 采集器选"本地目录"，路径指向 `examples/demo_repo/`（合成假凭据样例：config/database.txt/keys_rsa.pem/service_account.json 等）；
2. 立即运行 →【发现列表】应出现约 16 条凭据候选（GitHub PAT/AWS AK+SK 配对/私钥/服务账号 JSON/数据库连接串等）；
3. 核对：GitHub PAT 样例关联 2 个位置（多位置关联）；Twilio SID+AuthToken 配对加成（置信度 55→75、60→80）；默认全脱敏；
4. 再跑一次同来源 → 0 新增（幂等/去重生效）；
5. 【发现】→ 单条验证（需要真实凭据才演示 valid；合成的会 invalid）。

**在线演示（GitHub 真实渠道）**：

1. 在你自己的公开仓库放入 `examples/demo_repo/` 文件并提交推送（全部合成假值，文件头已注明；**切勿替换为真实凭据**）；
2. 设置页配置 GitHub Token（只读即可）→ 测试连接；
3. 新建来源：采集器 GitHub，仓库 `yourname/ccs-demo` → 立即运行 → 发现列表出现对应候选；
4. 改"持续监控"（间隔 120s）→ 推送新内容 → 观察分钟级自动发现。

## 六、数据管理与备份

| 路径 | 内容 | 备份要求 |
| --- | --- | --- |
| `data/app.db`（+-wal/-shm） | 业务数据库（SQLite WAL） | 常规备份 |
| `data/master.key` | 主密钥（Fernet 派生源） | **必须与数据库同时备份**；丢失=凭据密文永久不可解 |
| `data/github.token` | 本地开发用的 Token 文件（gitignored） | 敏感，不要外传 |
| `data/cache/` `data/tmp/` | 原始内容副本 / 解包临时区 | 可清理 |

- PostgreSQL 模式：连接串改环境变量即可（已实测 PG16）；
- 时区：库内全 UTC，界面默认 Asia/Shanghai（设置项 display_timezone）。

## 七、常见问题（FAQ）

| 现象 | 原因与处置 |
| --- | --- |
| GitHub 匿名扫描 403 | 共享出口 IP 配额耗尽（非故障）；配置 Token 即可 |
| Gitee 扫描中途停止，stop_reason=rate_limited | 匿名限流触发，系统按 Retry-After 优雅停止；生产建议配置 Gitee Token |
| 维基百科 403 | 已内置合规 UA；若自建站点请检查站点 UA 策略 |
| 验证结果是 network_error | 网络故障，**不判无效**；稍后重试 |
| 验证结果是 inconclusive | 平台返回 403（权限不足）等无法判断情形，勿当 invalid 处理 |
| 发现列表看不到原文 | 设计如此（默认脱敏）；需显式 reveal 且会留审计 |
| 端口 8000 打不开 | 检查后端是否启动；前端 dist 是否构建（或直接用仓库自带 dist） |
| Docker 内数据丢了 | 检查 ./data 卷挂载与 master.key 是否同卷保留 |
