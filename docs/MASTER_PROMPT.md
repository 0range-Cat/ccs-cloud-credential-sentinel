# MASTER_PROMPT — 任务完整约束存档

> 本文件固化"云上凭据泄露自动化检测与响应系统"任务的全部约束，供后续会话恢复上下文。
> 开发环境：zcode（GLM-5.3-Flash），允许多会话/子智能体协作；不假设专用能力，先检查再用。

## 一、背景与目标

网络安全创新大赛赛题"云上凭据泄露的自动化检测"。要求：
1) 多公开渠道检索泄露敏感凭据；2) 支持尽可能多的渠道与凭据类型；3) 争取分钟级发现；
4) 易于新增监控渠道。评价维度：渠道类别数与平台数、凭据类型数、扩展性、发现数量、
发现时间与公开时间差值。
必须交付：完整源码；技术说明书（原理/模块职责/实现说明）；支持的公开渠道列表；
凭据类型列表；可操作 Web 界面；部署说明；测试与评估报告；演示指南。

## 二、已确认的用户需求（既定条件）

1. Python 实现后端与采集检测逻辑。2. Windows 11 开发机 + Ubuntu 云服务器。
3. 不绑定固定配置，并发/规模可调。4. 手动指定范围 + 持续自动发现、增量采集。
5. 七类渠道全部属于建设范围，不能完成 GitHub 即宣布完成。
6. 凭据覆盖由本团队调研提出并落实。7. 发现→存储；验证独立，默认不自动验证。
8. 单条/批量/可选自动验证。9. 验证仅判断有效性，不做其他操作。
10. 单人使用、中文界面、无复杂权限体系。11. 界面与导出可选脱敏。
12. 采集账号/Token/接口地址在【设置】页配置并附指引。
13. 用户目前仅有自己的 GitHub 仓库可用于真实渠道测试。
14. Git 管理，每个可独立验证的改动即提交。15. 先设计后动手，维护开发记录/部署/目录/TODO。
16. 无固定截止时间，分阶段推进，每阶段可运行、检查、演示。

## 三、执行原则

- 已确认需求视为既定条件，不反复询问；常规细节自行判断并在文档说明依据。
- 仅在确缺外部信息且无法继续时提问，同时继续不依赖该信息的工作。
- 渠道/规则/验证器必须插件化扩展。
- 区分：规划支持 / 代码已实现 / 离线测试通过 / 真实接入验证通过。
- 空接口、静态页面、模拟数据不算支持；平台受限时记录障碍、配置需求与剩余工作，不伪造完成。
- 外部阻塞不放弃渠道，保留任务继续其他模块。不承诺任意平台/硬件的固定发现延迟。
- 不把内置规则总数宣传为实际支持的类型数。
- 运行时检测链路不依赖 LLM；开发用 AI 不代表系统依赖付费模型。

## 四、技术调研与默认技术栈

先调研开源工具再定复用方案：Gitleaks（离线扫描/规则/结果格式）、TruffleHog（检测器/
配对/验证及实际请求行为）、detect-secrets（插件/熵/误报抑制）、GitHub/Gitee 官方接口现状、
容器镜像/APK/小程序产物成熟解析工具。
调研必须核实：版本/维护/许可证；Windows 与 Ubuntu 可用性；Python 集成方式与子进程调用、
结果解析；是否默认在线验证；渠道与类型实际支持度；新增规则/采集器/验证器方式。
来源链接、调研日期、版本、复用范围、许可证要求记入 docs/RESEARCH.md；联网受限标待核实，不编造。
默认技术栈：Python 3.11+ / FastAPI / Pydantic；SQLAlchemy 2 / Alembic；SQLite(WAL)→PostgreSQL；
httpx 异步采集；成熟调度库+持久化作业；Vue3/TS/Vite/Element Plus；pytest+浏览器自动化；
Windows/Ubuntu 原生 + Docker Compose。模块化单体，不引入 K8s/Redis 队列。
轻量模式控制工作器与写并发；后台任务不能只在内存；任务/游标/结果持久化可恢复。
允许调整选型但先写理由与迁移影响；锁定依赖版本，可复现安装。

## 五、渠道范围与采集方式

七类渠道（每渠道明确：入口/支持内容/认证/自动发现/增量策略/限制/测试方法/状态）：
1. 代码托管：GitHub、Gitee；仓库/组织/用户/关键词输入；当前文件+Git 历史；
   Gist/Issue/评论按平台能力扩展；不假定代码搜索实时完整；索引延迟/上限/分页必须记录；
   轮询/事件/Webhook 组合；私有仓库测试不算公开发现测试。
2. Wiki：至少一个 MediaWiki 兼容适配器；页面/修订/最近更改增量；保留页面与修订来源。
3. 微博：公开检索或监控适配器；优先官方接口，需账号走设置页；明确关键词/账号/正文/附件支持；
   登录过期/限流/验证码返回明确状态，不绕过访问控制。
4. 知识分享：CSDN/博客园/掘金/StackOverflow 等，以实际实现为准，不把通用抓取虚报为多平台；
   正文/代码块/可获取评论附件；另提供通用 URL/RSS/Atom/Sitemap 采集。
5. 容器镜像：OCI/Docker Registry 兼容接口与公开来源；指定镜像/仓库/标签监控；
   digest 识别版本避免重复拉取；检查配置/构建历史/镜像层文件；
   区分当前文件系统可见泄露与历史层残留；处理 whiteout 语义；
   限制镜像大小/解包大小/临时空间/并发。
6. App：完整支持 Android APK（清单/资源/配置/字符串/代码产物）；公开下载入口版本监控+手动上传；
   成熟静态分析，不执行未知应用；记录包名/版本/来源/包内路径；
   IPA 等后续扩展，未实现不计入；上传扫描≠公开渠道自动监控。
7. 小程序：合法取得的包/构建产物/解包目录；脚本/配置/静态资源；可访问公开入口的版本监控；
   明确生态/格式/版本；不假设能取到全部线上小程序源码；不含绕过加密/鉴权能力。
另支持本地目录、Git 仓库副本、压缩包导入作为分析测试入口（不虚增渠道类别数）。
自动发现默认：种子（组织/域名/关键词/仓库/账号/URL）→生成检索任务→候选内容→
按配置扩展关联入口→持续增量。每个任务配置或继承：扫描范围与包含排除规则、
扩展深度与候选上限、调度间隔/并发/速率、大小限制与运行时限、历史回溯范围与缓存保留。

## 六、凭据类型与检测策略

类型注册表逐步实现：云厂商（AWS/阿里云/腾讯云/华为云/Azure/GCP 及对象存储等）；
代码与制品平台（GitHub/GitLab/Gitee/包管理/镜像仓库）；API Key（AI/邮件/短信/第三方）；
OAuth Client Secret 与访问 Token；SSH/RSA/EC/OpenSSH 私钥；服务账号密钥与 JSON 配置；
MySQL/PostgreSQL/MongoDB/Redis/SQLServer 连接串；配置脚本环境文件中明确上下文的账号密码；
.env/YAML/JSON/INI/XML/连接 URL 载体。
规则字段：稳定 ID、类型、厂商、版本、来源与许可证、适用格式、提取组、关联字段、
误报过滤、置信度规则、正反样本、验证器关联。
检测组合：前缀正则；格式解析与字段语义；变量名/服务域名上下文；熵与长度；
示例/占位符/重复字符/已知假样本过滤；有边界编码解码；AK/SK、用户名/密码/地址配对。
注意：高熵≠凭据；配对限于合理上下文；歧义保留候选并说明缺失；
弱特征类型依赖上下文；截断/加密/格式错误/缺字段明确表示；正则/递归/解码有资源限制；
私钥格式正确与加密与否≠线上有效。
不强行接入多个功能重叠引擎；选定一个主要离线引擎+补充规则+统一结果转换层；
检测阶段禁用第三方引擎自带在线验证。

## 七、发现记录、去重与时间模型

核心实体：采集源与配置；监控任务/执行批次/采集游标；来源内容及版本；凭据候选与去重凭据实体；
凭据出现位置；检测证据与人工复核记录；验证作业与验证历史；规则/插件/能力清单。
"同一凭据"与"同一次出现"分开建模。
凭据记录：类型/厂商/关联字段/置信度/匹配规则与版本/复核状态/首末发现时间/受保护内容/脱敏预览/稳定指纹。
位置记录：类别/平台/原始 URL/仓库或账号/路径/行号或定位/提交·修订·digest·应用版本/
脱敏上下文/内容哈希/发现批次。
时间字段：source_published_at（需证据与可信度）、source_updated_at、fetched_at、detected_at、
first_seen_at/last_seen_at、verified_at、commit_authored_at 等单独记录。
Git 提交时间/文件修改时间/首次抓取时间不得冒充公开时间；未知存 null 显示"未知"；
UTC 存储，界面配置时区显示，默认 Asia/Shanghai。
去重：同凭据多位置；同位置重复扫描不重复建事件，更新 last_seen 保留历史；
不同账号/端点/组合不错误合并；受保护稳定指纹（低熵密码不用普通哈希作公开标识）；
失效/误报/无法验证记录不自动删除。

## 八、独立的最小化验证模块

默认：发现→入库→展示，不自动验证。入口：单条/批量/显式开启自动（按任务/类型/验证器控制）；
可配重新验证间隔、结果有效期、并发限制。验证器与采集、检测完全解耦；声明：适用类型/
所需字段/固定端点或受限目标规则/方法与认证协议/预期响应/状态判断/超时重试限流/最小验证符合性。
必须：最小操作；不读业务数据；不枚举资源（云资源/仓库/桶/表/模型）；不执行命令/SQL/上传下载/创建删除/配置修改；
不经计费业务功能判断；不因库自带验证直接信任；不发无关第三方；防重定向泄露凭据；
不把采集地址直接当验证目标。可用文档明确的最小认证/身份确认接口；
无合规验证办法→标"不支持最小在线验证"，保留检测。
SSH 私钥/系统密码/数据库密码：无目标信息或无法保证仅认证时不尝试；格式校验≠在线有效。
状态：not_requested/queued/running/valid/invalid/inconclusive/missing_context/unsupported/
rate_limited/network_error/error。
规则：401/403 不一律 invalid；权限不足与认证失败分开；限流/网络故障/服务不可用≠invalid；
仅对暂时性错误重试；错误配对/重复验证/高频失败受限；每次验证追加历史；
保存证据摘要/验证器版本/时间，不把完整敏感响应写日志。

## 九、界面与设置

中文界面：1) 总览（渠道/类型/时间/状态统计；待处理候选、去重凭据、验证分布；
任务状态/队列积压/失败限流；时延分布与样本数）；
2) 监控任务（手动+持续；范围/种子/过滤/间隔/预算；启停取消重试；进度与可读失败原因）；
3) 发现列表与详情（搜索筛选排序分页；类型/置信度/复核/验证状态；位置/上下文/时间/规则依据；
多位置关联；单条与批量验证；标记真实/误报/忽略/恢复）；
4) 验证中心（队列/结果/历史；自动验证配置；不支持/缺字段/限流/失败原因）；
5) 渠道与规则（真实能力与接入状态；采集器配置/规则启停/忽略规则；测试规则不默认线上验证）；
6) 设置（账号 Token；接口地址/代理/超时/速率；并发/存储/保留/调度默认；验证策略；
脱敏与导出默认；连接测试说明测试对象，用采集账号，不用发现凭据）。
导出：CSV+JSON；可选字段/筛选/脱敏；CSV 防公式注入；大导出不阻塞。
脱敏：默认脱敏；可选显示/导出原文；采集账号与发现凭据分开管理；非必要 API 不返回原文；
关闭界面脱敏不把凭据写入日志/URL/异常/Git。
敏感数据持久化加密；主密钥环境变量或本地密钥文件，不与密文/代码同提交；
备份恢复文档说明主密钥依赖；本地默认回环绑定；远程简单单用户保护或受保护反代。

## 十、误报处理与统计口径

先保留候选再分级复核；记录置信度与依据；人工标记误报/确认/忽略/恢复；
按规则/路径/内容指纹等作用范围建忽略规则；忽略有原因有记录，不删证据；
区分"真实但失效"与"误报"。
分别统计：检测命中次数；去重凭据数；唯一泄露位置数；疑似候选数；人工确认数；
当前验证有效/失效/无法判断数。复核状态、置信度、验证状态三维度独立，不互相覆盖。
有重叠的指标必须解释，不相加冒充总量。口径：类别数与平台数分开；自动监控与导入分开；
可检测类型与可验证类型分开；别名/变体/重复规则不拆分凑数；实现状态与真实接入状态分开。

## 十一、性能、持续运行与可靠性

单机持续运行：并发/频率/批大小/内容限制/存储可配；条件请求/内容哈希/游标/版本缓存；
稳定轮询加抖动；限流遵循 Retry-After；单渠道失败不拖垮其他；
任务状态持久化、重启恢复、幂等；定时任务避免重叠；暂停/取消/超时/断点语义明确；
缓存与临时目录有配额与清理；解包防路径穿越/符号链接/解压炸弹；背压控制采集与队列。
时效：可控可持续访问、有可靠发布时间的测试源，配置合理轮询后分钟级为目标；
记录 P50/P95、失败率、队列延迟、资源占用；平台索引延迟/抓取延迟/检测处理延迟分开说明；
无可靠公开时间的样本不参与时延计算。不编造吞吐承诺；基准报告写明环境与版本。

## 十二、测试与验收

A 离线可重复：规则正例/反例/占位符/边界；配对/去重/多位置/误报复核/时间缺失；
平台响应样例（分页/增量/限流/认证过期/异常格式）；验证器 HTTP/协议模拟（有效/无效/未知/超时/限流）；
验证默认关闭时扫描不发任何验证请求；验证器不发枚举/读数据/写操作请求。
B 端到端：设置→建任务→采集→检测→入库→查询→复核→单条批量验证→脱敏切换→导出→暂停恢复；
重启恢复；重复扫描幂等；同凭据多位置关联；Windows/Ubuntu 启动；SQLite/PostgreSQL；
容器层/APK/小程序解析链路。
C 真实渠道：用户仅有自己的 GitHub 仓库；演示步骤可由用户执行；仅用明确合成、无法认证的测试凭据
做公开检测演示；私有与公开测试分别标注；在线验证用用户自有允许测试的凭据经本地配置提供，
不入公开仓库；缺账号/产物的渠道标未完成真实接入验收；模拟 valid 不计入真实有效数。
评估报告：渠道支持范围与限制；类型检测与最小验证能力；标注样本精确率/召回率/误报分析；
调优样本与独立评估样本分离；按类型分别报告；去重效果；时延与样本数与时间依据；
资源占用；未完成项/外部限制/复现步骤。
没有测试证据的能力不得标验收通过；不为样板代码机械堆覆盖率。

## 十四、多会话与子智能体协作

先立契约再并行。职责：主控（架构/契约/迁移协调/分配/集成验收）、采集、检测、验证、前端、测试与文档。
按可用并发与依赖分配，不为并行强拆；主控负责最终闭环。
子任务说明含：目标与编号/需读文档/分支/允许修改范围/输入输出接口/前置依赖/必须实现行为/
验收命令/禁改共享部分/交付与交接。
zcode 支持子智能体则直接使用；否则生成 docs/tasks/ 可复制提示词，不假装已运行。
每次会话结束更新 HANDOFF.md：分支与最近提交/完成与未完成任务/检查与结果/失败与阻塞与缺配置/
下一步/关键决策/未提交原因；不记录真实密钥。新会话先读规则/需求/架构/接口/TODO/交接，核对 Git 状态。

## 十五、实施阶段

阶段0 调研与设计：环境/仓库/工具检查；文档与 Git 规范；核实开源工具与渠道入口；
定义模型/状态/插件契约/能力矩阵/验收标准；分阶段 TODO；完成设计后继续实现，不以"计划完成"结束。
阶段1 最小闭环：可运行后端/数据库/中文界面/设置；GitHub 指定仓库与本地仓库扫描；
首批规则/入库/去重/多位置；默认不验证；误报标记/脱敏/导出；自有 GitHub 仓库演示路径。
阶段2 持续发现与网页渠道：持久化调度/增量/恢复/限流；Gitee/Wiki/微博/知识分享；
组织/域名/关键词种子发现；时间模型与渠道状态展示。
阶段3 制品渠道：容器镜像与历史层；APK；小程序产物与可接入公开入口；上传与公开采集分别验收。
阶段4 验证与覆盖扩展：独立验证队列；单条/批量/可选自动；逐个审查接入最小验证接口；
补齐主要类型/配对/误报规则；接口稳定后可与部分渠道并行。
阶段5 集成评估交付：三平台部署验证；端到端/恢复/性能/异常测试；更新矩阵与全部交付文档；
可重复演示流程与评估报告。
每阶段结束：运行检查→修复失败→更新文档/TODO/交接→提交 Git→说明成果与限制→继续下一阶段。

## 十六、最终完成标准

同时满足：核心流程可运行；七类渠道均有具体实现与清晰接入测试状态；主要类型有真实规则与正反样例；
验证默认关闭且支持三种模式；验证严格最小认证；统计/去重/时间口径明确且经测试；
Windows/Ubuntu 部署可复现；文档与代码一致、四项赛题交付件齐全；Git/测试证据/任务状态可追溯；
无模拟/未接入/未验证功能被宣传为完成。
外部条件致部分无法验收时，交付"已实现部分及待验收项"，不标整体全部完成。
