# GitHub 演示指南（用户可操作）

> 目的：用你自己的 GitHub 仓库完成"公开渠道发现泄露凭据"的真实接入验收。
> 安全边界：演示仅使用**合成、无法认证**的测试凭据；不会也不会需要任何真实凭据；
> 在线验证功能默认关闭，若要演示验证，只允许使用你自己持有、允许测试的凭据并仅通过本地配置提供。

## 前置条件

- 你的 GitHub 账号与一个**公开**仓库（例如新建 `ccs-demo`）。
- 本机可访问 github.com（当前开发网络 `api.github.com` 返回 403，为共享出口 IP 配额问题，
  在你的常用网络环境执行即可）。
- 系统已启动（见 README 快速启动），浏览器打开 http://127.0.0.1:8000。

## 步骤 1：向你的公开仓库放入合成泄露样例

1. 把 `examples/demo_repo/` 下的文件复制到你自己的公开仓库并提交推送
   （内容全部为合成假值，文件头已注明；请勿替换为真实凭据）。
2. 记下仓库标识，如 `yourname/ccs-demo`。

## 步骤 2：配置采集账号（设置页）

1. 界面 →【设置】→"平台采集账号"→ 填入 GitHub Token（可选但建议：
   Settings → Developer settings → Personal access tokens，只读即可）。
   Token 经 Fernet 加密存储于本地数据库，不会出现在任何日志与导出中。
2. 点击【测试连接】：选择目标 `github`、填入仓库标识。
   该测试只使用你在设置页配置的采集账号，与扫描发现的任何凭据无关。

## 步骤 3：创建监控任务

1. 界面 →【监控任务】→【新建来源】：
   - 采集器：`GitHub 仓库扫描`
   - 仓库：`yourname/ccs-demo`
   - 模式：先选"手动"，验证链路后再改为"持续监控"（间隔建议 120–600 秒）。
2. 点击【立即运行】。

## 步骤 4：检查发现结果

1. 【发现列表】应出现若干凭据候选（GitHub PAT / AWS AK/SK / 私钥 / 服务账号 JSON /
   数据库连接串 / 邮件与协作平台密钥等，对应 examples/demo_repo 中投放的样本）。
2. 核对：
   - 列表默认脱敏（`ghp_4a9****xxxx` 形式）；
   - 详情页可见来源 URL、路径、行号、脱敏上下文、规则依据；
   - 时间字段：`发布时间` 显示"未知"（GitHub 文件级公开时间不可得——这是如实口径），
     `首次/最近发现时间` 为本次扫描时间。
3. 【总览】查看统计口径：检测命中 / 去重凭据 / 唯一位置分开计数。

## 步骤 5：持续监控与分钟级发现演示

1. 把任务改为"持续监控"，间隔 120 秒。
2. 在 GitHub 上新增一个含合成凭据的文件并推送。
3. 观察发现延迟：从 git push 到界面出现候选的时间。
   记录 3–5 次样本（含时间戳）回填到 docs/EVALUATION.md。
   注意：该延迟 = 轮询间隔 + 采集 + 检测 + 入库，不含平台索引延迟（我们直接读仓库树）。

## 步骤 6：复核 / 验证 / 导出

1. 在发现列表把任意候选标记为"误报/确认/忽略"，验证复核留痕。
2. 验证演示（可选）：GitHub PAT 类型候选 →【提交验证】→【验证中心】查看
   valid / invalid / rate_limited 状态与历史。
   注意：样例中的 PAT 是合成假值，预期结果为 `invalid`——这本身就是正确行为。
   自动验证开关默认关闭；开启后仅按策略对支持的类型执行最小认证请求。
3. 导出：CSV / JSON，勾选/取消脱敏对比；CSV 已做公式注入防护。
